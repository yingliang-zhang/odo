## 2. Current Architecture (from code)

### Memory layers (ADR-0003)

Odo has 6 memory layers, each with a specific authority and lifecycle:

| Layer | File | Scope | Who writes | When | Cap |
|---|---|---|---|---|---|
| user.md | `~/.odo/user.md` | Global (all projects) | User (manual) or learner (via apply_memory) | Manual or distill→propose→apply | 4KB |
| memory.md | `<project>/.odo/memory.md` | Per-project | User (manual) or learner (via apply_memory) | Manual or distill→propose→apply | TBD |
| pins.md | `<project>/.odo/pins.md` | Per-project | User (manual, via Pin button) | User clicks Pin | 2KB |
| wiki notes | `<project>/wiki/<ws>-epoch-N.md` | Per-workstream | Daemon (distill) | User clicks Distill | 12KB each |
| topic pages | `<project>/wiki/topics/*.md` | Per-project | Daemon (curate) | User clicks Curate | 2KB index |
| ledger.md | `<project>/.odo/ledger.md` | Per-project | Daemon (distill) | Auto on distill | — |

### Injection order (buildPrompt)

Every prompt gets: user.md → memory.md → pins → wiki/index.md → recalled wiki notes → skills → user text

### AGENTS.md generation (server.go:326-356)

On every bootstrap, `generateAgentsMD()` writes `.odo/AGENTS.md`:
1. Header: "auto-generated by Odo daemon, do not edit manually"
2. "Odo injects current user memory, project rules, pins, wiki, and recalled notes in the prompt prefix. Treat them as authoritative. If OMP's hindsight memory conflicts with the prompt, follow the prompt."
3. Appends `.odo/memory.md` content if it exists
4. Appends `.odo/pins.md` content if it exists
5. Writes to `.odo/AGENTS.md`

### Distill→learner→propose→apply pipeline

1. User clicks Distill → daemon summarizes conversation into a wiki note (epoch note)
2. Learner analyzes the conversation + epoch → proposes behavior rules
3. Proposals are classified by a tri-model gate: auto_discard (all reject) / human_gate (anything else)
4. User reviews proposals in MemoryReviewPanel → clicks Apply
5. `apply_memory` writes approved rules to `memory.md` or `user.md` (target specified per proposal)
6. If a rule supersedes an old one, the old rule is moved to `memory-archive.md` (demotion, never deleted)

### Key distinction

- `memory.md` and `user.md` are BOTH writable by the learner (via apply_memory) AND by the user (manual edit)
- `pins.md` is ONLY user-authored (Pin button or manual edit), never auto-written
- `AGENTS.md` is ONLY auto-generated (never manual, never by learner)
- The distill→learner pipeline is the SAME mechanism for both memory.md and user.md — the learner proposes, the user approves, the daemon writes

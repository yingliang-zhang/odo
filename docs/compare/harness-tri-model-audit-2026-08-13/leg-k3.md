## D. Q3 ranked feature-borrow list for Odo

**1. Risk-tagged review receipts** — persist structured classification (risk class, outcome, rationale ref) on every automated review/approval decision as first-class journaled events, later queryable by streak.
- **Evidence**: `codex:codex-rs/core/src/guardian/review.rs:350-439` (GuardianAssessmentStatus persisted in rollout items) + `core/src/guardian/metrics.rs:115-119`; API commit "Persist security risk scores in rollout history (#38363)".
- **Who has it**: codex (best); dsh has the `approval/asked`+`decided` pair but no risk class (`dsh:docs/subsystems/approval.md`); grok only a sandbox-events JSONL.
- **Map to Odo**: `internal/ipc/review.go` + `runverdict.go` — tag each MoA `review_action` verdict leg with a mechanical risk class (protected-path touched / supply-chain / test-weakening, classes already computed in `autoland.go`); surfaces in `internal/ipc/autonomy.go` (`odo autonomy audit`) — exactly the per-class evidence the A1 ratchet is waiting for.
- **Cost**: **S** — add fields to a typed journal event + audit join; no new subsystems.
- **Fit risk**: low. Borrow the *receipts*, not the judge — codex trusts one model to classify; Odo keeps unanimous MoA verdicts and merely records why.
- **P0 / High**.

**2. Structured verdict output for MoA legs** — constrain each review leg's final answer to a JSON schema (verdict/findings/confidence) instead of parsing free text.
- **Evidence**: `codex:codex-rs/exec/src/cli.rs:50-58` (`--output-schema FILE`, JSON-Schema-constrained final message); `grok:xai-grok-pager/src/headless/reducer/mod.rs:368-371` (structured message streams).
- **Who has it**: codex best (schema-constrained answer); grok/dsh structured streams only.
- **Map to Odo**: `internal/adapter/omp.go` (leg prompt/emission) + `internal/ipc/review.go` (verdict parsing path).
- **Cost**: **S** if OMP exposes an output-schema/mode flag; **M** if Odo must validate-and-reask prompt-side.
- **Fit risk**: **Odo doesn't own the agent loop** — capability depends entirely on OMP flags; absent schema support, the fallback is schema-in-prompt + strict validator (still worthwhile, but honest cost is M not S).
- **P1 / Med**.

**3. Declarative policy file for the mechanical gates** — move protected-path / supply-chain / new-topdir / test-weakening decisions from Go constants into a user-editable rule file with explicit precedence (deny>ask>allow) and per-decision journaled justification.
- **Evidence**: `codex:codex-rs/execpolicy/README.md` (Starlark `prefix_rule(pattern, decision=allow|prompt|forbidden, justification, match/not_match)`); `grok:docs/user-guide/22-permissions-and-safety.md:100-200` (rule grammar, config chain, and `requirements.toml` admin lockout).
- **Who has it**: grok most ergonomic grammar; codex most expressive DSL; dsh's presets too coarse to copy.
- **Map to Odo**: `internal/ipc/autoland.go` gate blocks → rule evaluator over e.g. `.odo/rules`, compiled defaults remain the base layer; admin-lockout idea (grok) maps to "rule edits must pass the gate themselves".
- **Cost**: **M** — parser, precedence tests, justification journaling; no platform deps.
- **Fit risk**: adversarial: a writable policy surface is a ratchet-bypass surface — one bad rule neutralizes M16's gates. Ship read-mostly (defaults compiled; file only tightens, never loosens, at first). Cost of doing nothing: today's gates are code, so tuning them costs a commit each time.
- **P1 / High**.

**4. Turn-fork / rewind with journal-preserving semantics** — branch a conversation at journal event N into a new conversation seeded with the prefix; "rewind" marks later events superseded without deletion.
- **Evidence**: `codex:codex-rs/thread-store/src/local/revert_thread.rs:19-121` (durable revert, same thread id, new immutable rollout file) + `rollout_migration/` (offline migration planner); `dsh:docs/architecture.md` (`ctx.sessions.fork(source, boundary?)`, delegationDepth in header); `grok:docs/user-guide/17-sessions.md` (`--fork-session --worktree`, `/rewind`, `rewind_points.jsonl`).
- **Who has it**: all three; codex's id-preserving immutable revert is the cleanest model; grok's worktree-fork is the nicest UX nuance.
- **Map to Odo**: `internal/store` (fork = new conversation_id + copied prefix events carrying `forked_from` seq receipts) + GUI workstream action; extends the M12 verbatim-replay machinery, append-only invariant untouched (fork copies, never edits).
- **Cost**: **M** — store op + GUI affordance are easy; recall/distiller scoping (epoch notes must not leak across branches unprefixed) is the real work.
- **Fit risk**: Odo's long-autonomy goal makes "abandon a bad turn, keep the evidence" eventually mandatory; risk is memory-layer scope confusion, mitigated by existing per-run sha16 receipts.
- **P1 / Med**.

**5. Whole-process sandbox profile for agent launches** — run each agent child under a kernel-enforced FS/net profile (workspace-write equivalent), fail-closed.
- **Evidence**: `dsh:native/landlock-run/README.md` (~300-line C11 Landlock launcher) + `packages/sandbox/sandbox-local/README.md` (4-backend seam, bwrap→Landlock probe order, "silent unconfined passthrough never legal"); `grok:docs/user-guide/18-sandbox.md` (whole-process irreversible profiles via vendored nono); `codex:codex-rs/linux-sandbox/README.md` + `sandboxing/src/seatbelt.rs`.
- **Who has it**: all three (identical triad!) — dsh most thorough, grok's whole-process model the most transplantable (Odo would wrap the OMP process, not individual tools).
- **Map to Odo**: `internal/adapter/omp.go` spawn site — Seatbelt profile (macOS-first: allow R/W on worktree + tmp, RO elsewhere, no net restriction initially).
- **Cost**: **L** — profile authoring, allowlisting memory/skills/wiki paths, tool-breakage matrix; `sandbox-exec` is deprecated on modern macOS (both dsh and codex ship it anyway).
- **Fit risk**: Odo README explicitly lists "No sandbox containment" as a deliberate absence; worktree isolation + unanimous auto-land gates already bound the blast radius for a single-user box. Defer until a real incident; the three-way industry convergence is why it stays on the list at P2 rather than dropping.
- **P2 / High**.

**6. Orphan-turn synthetic close on cold boot** — on daemon start, close any run left `running` from a crash by appending a synthetic `agent_interrupted` event; never truncate, never leave dangling.
- **Evidence**: `dsh:docs/subsystems/persistence.md` (cold load closes orphaned `turn/start` with synthetic `turn/end {kind:'interrupted'}`); API commit codex "Add interrupted turn recovery (#38303)"; `grok:~/.grok/sessions/.../signals.json` (`docs/user-guide/17-sessions.md:20-45`).

- **Map to Odo**: `internal/ipc/server.go` startup + `internal/store` event append; makes `odo autonomy audit` streak math crash-honest, and `odo journal` replay terminates cleanly.

- **P2 / High**.

**7. Per-model capability catalog for settings** — vendored per-model catalog (supported reasoning efforts, modalities, limits) driving picker menus and **rejecting** known-invalid config pre-flight (never silently clamping).

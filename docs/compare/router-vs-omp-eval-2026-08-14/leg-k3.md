## A. Recommendation

**B (expand direct-router deliberately), with a narrow blast radius: migrate the three summarization one-shots (distill, learner, curator) from OMP print-mode to `moa.Query`, route the future Design-MoA consolidator through `moa`, productize the existing read-only tool loop for design legs, keep OMP for every write-capable worktree run.** Runner-up: **A (formalize status quo, fix gaps in place)**. Flip trigger B→A: if the sudo gateway's SLO or protocol stability degrades (journled `memory_update{layer:"distill",cause:"failed"}` / panel error rate climbing), or OMP ships exact-prompt echo + structured-output schema (then the receipts gap closes and A+D dominates).

Ground truth discovered during verification that reframes the question: the status-quo boundary is **not** "OMP=write, moa=think". Distill (`internal/ipc/server.go:2541` doc: "a one-shot run of the default adapter" + `runDistillAgent` server.go:3491), learner (`internal/ipc/learner.go:526`), and curator (`internal/ipc/curator.go:472`) are *thinking tasks* (completion-in, daemon-parsed-out, daemon-written artifacts) that **pay full OMP agent-spawn cost** — wrapper timeouts, print-mode recap-only exits, session-JSONL forensics — while using **none** of OMP's loop (no edits, no shell). Meanwhile review/panel/vision/skill-gate already prove the direct path works (`server.go:2051 reviewWithModel`, `server.go:2161 /panel`, `server.go:2378 /vision`, `skills_gate.go:84`). So the decision is really: *finish the partial migration the codebase already started*, or consolidate back.

Three facts make B right-sized, not maximal:

1. **The receipts story is asymmetric.** Send-path receipt closure is daemon-enforced and fail-closed (`assertPromptReceipts` server.go:1042, `assembleRunPrompt` server.go:1098); slash path same (`assertSlashReceipts` slashctx.go:183). But the exemption ledger (server.go:1027-1040) concedes distill prompts are only attested by *derivation* ("pure f(journal events)"). Under OMP, whatever OMP adds (system prompt, tools, skills, compaction) is invisible; under moa, model-visible ⟺ logged is *literally* enumerable: system + one user message + tools[].
2. **The observed failure class targets exactly the one-shots.** Print-mode recap-only exit with recovery "only from session JSONL" (harness-audit §0 leg 3; recovery code: `parseSessionJSONL` omp.go:830), exact-UUID resume exiting instantly, 900s mid-gather kill (gui-audit §0 leg 3), wrapper `[OMP_TIMEOUT]` diagnostics advising `--resume <uuid>` (omp_with_timeout.sh:~1095). Distill/learner/curate run in *this* print-mode shape today; a learner parse/timeout failure degrades silently (learner.go:527-554) — the moat's memory pipeline eats the harness's weakest mode.
3. **Everything Option B needs is already paid for.** The quirk tail (thinking verbatim replay / kimi 400, budget escalation ledger, stop whitelist, 900s floor: `moa/client.go:40-73,176-186,329-460`), per-model budgets (`modelspec.Lookup`), read-only scoped executor with journaled audits (`fstools.go:newFSToolExecutor`, `moaFSTools`), and fence-tolerant JSON parsers (`parseLearnerOutput` learner.go:251, `parseCuratorOutput` curator.go:222) all exist. Migration is deleting `runOneShot` usage on three call sites, not building anything new.

## E. Risks & failure modes (top-2 per option)

- **A**: (1) boundary stays unwritten folklore — 16 moa references in server.go with no ADR means the next contributor guesses; (2) the distill anomaly calcifies: the memory pipeline (the moat, README shape section) keeps riding OMP's weakest mode (print-mode outages observed tonight) while the by-derivation exemption (server.go:1028) leaves "what did the distill actually see" unanswerable at wire level.
- **B**: (1) *Single-gateway concentration widens* — distill/learner/curator join review/panel on `coding.sudoai.cc`: one outage now stalls the memory pipeline too (mitigation: W1 dark-launch flag; note OMP chat runs already route through the same sudo provider via models.yml, so concentration is already near-total). (2) *Timeout semantics shift* — worst-case distill at escalation cap ≈ `900 + 65536/120 · k` moa/client.go:60-66 ceilings exceed the current 10-min `distillTimeout` (server.go:2539); idle auto-distill windows could stretch; needs a per-call deadline policy choice, not a default accept.
- **C**: (1) tonight's observed failure modes (recap-only exits, UUID-resume no-op, mid-gather timeout — gui-audit §0 leg 3) become the failure mode of *MoA review legs and /panel*, at N-leg fan-out prices; (2) model-visible⟺logged (audit's P0 #2, harness-audit §5) becomes permanently unassertible — Odo's core receipts claim (README "what exactly did run N see?") degrades to "what Odo *gave* OMP".
- **D**: (1) upstream cadence/leverage risk — the peer set's posture is zero external PRs (harness-audit §4); feature requests may stall indefinitely while B sits blocked if sequenced as prerequisite (hence: parallel, never gating); (2) even if shipped, echo flags attest what OMP *recorded*, and the recorder is OMP — a weaker claim than daemon-enforced journaled requests on direct paths.
- **E**: (1) rebuild scope is a different product — managed loop, edit/shell/policy tools, streaming, sessions, resume (codex: session management alone is a 7,010-line sub-app, gui-audit §0; `close-the-loop-before-hardening` principle in README inverts: hardening long before any closed loop); (2) flag/quirk surface restarts from zero — OMP's per-provider quirks (effort flags, compaction behavior, stream protocol) get rediscovered one incident at a time, while upstream improvements stop arriving for free.

## F. What would change my mind

Falsifiable conditions against Recommendation B:

1. **OMP capability landing**: OMP ships a structured-output flag **and** a verifiable exact-request echo (the two asks in W0/W4). Test: assert visible⟺logged on an adapter run passes with OMP-supplied evidence. If both boat within one release cycle, flip to **A+D**: run all MoA legs over OMP, keep moa only for /panel//vision.
2. **Gateway reliability**: journaled failure counters (distill `memory_update{cause:"failed"}` rows; panel `Error` fields in `PanelResult`, server.go:2239) show direct-path failure rate above the OMP-print baseline over ~30 days of use, or the sudo gateway breaks the Anthropic-Messages surface twice in a quarter (each break = a quirk-tail reopen in moa/client.go's whitelist/replay logic). Then W1/W2 roll back behind the dark-launch flag and the boundary retreats to A.
3. **One-shot cost surprise**: W1's journaled `output_tokens`/`escalations` on distill markers (the same ledger discipline the moa client already uses, server.go:2241-2248) show distill cost materially *rising* versus the orchestrator-route OMP runs it replaces (e.g., repeated cap-exhausted re-issues on 256 KiB windows, distillPromptBytesCap server.go:3768). Data lives in the journal; if it says mo, retreat.
4. **Design-MoA turns stateful**: if proposal legs empirically need deliberation beyond the 16-round read-only loop (moq `maxToolRounds`, client.go:70) — i.e., they need to *write and re-read* scratch artifacts mid-leg — proposal legs move back to OMP (W3 scope shrinks; consolidator-on-moa stands).
5. **OMP abandonment signal**: if OMP maintenance stalls (no releases addressing the print-mode/ resume failure class in ~2 cycles while Odo hits them repeatedly), that is the only condition under which **E** leaves the floor — as a *targeted* read-write runner for the settlement ladder, not a general reimplementation.

## Q1 — Exact new home: inside `learningPromotionVerdict`, with a fourth verdict path attached

**Home: inside `learningPromotionVerdict` (`learning_measure.go:442-481`), not a separate canary-stage gate.** Three structural reasons:

1. **§5.3 is AST-pinned.** Gate predicates may not declare `[]store.Event` (`learning_measure_test.go:333-336`, `382-384`) — a separate "efficacy gate" reading evidence would violate the pin the moment it needed more than the measure struct. Everything f′ needs (live reject/weak counts, outcome floors, epoch) is already in or derivable from `learningCohortMeasure`.
2. **The canary drop convention already cites the measure row, not a `learning_gate` family.** The existing canary drop journals `learning_stage{canary→dropped, cause:"harmful_tuple", measure_seq}` (`learning_stages.go:486-489`). A new third gate-row family for the canary stage would create the second convention this repo everywhere prohibits (cf. the freeze-set "ONE fold, three consumers" doctrine, `learning_measure.go` header).
3. **Journal safety.** The verdict needs one new key — the canary-entry epoch as an integer. Existing `WindowFrom` is a `created_at` string; age-in-epochs is the comparison needed for the grace rule below. Add `stage_epoch` to the journaled measure row (additive key, ADR-0002-safe), populated by the driver `learningCanaryMeasure`, which already folds exactly this value (`learningStageMainEpochAt`, `learning_stages.go:493`). Gate signature stays `(m, cand)` — AST pin keeps passing.

**Stay-or-drop: staged, not either/or.**

- Below paired minimums (`Canary.Outcomes < 10 || Live.Outcomes < 10`, `learning_measure.go:456-460`): vacuity is **unjudgeable** → `""` (stay; existing path, evidence ages).
- Minimums met ∧ `liveHarm = 0` ∧ residence ≥ 3 main-lane epochs: **drop**, new stage cause `efficacy_vacuity`. The grace reuses `learningShadowAgingEpochs = 3` (`learning_stages.go:157`) — the world gets three epochs to produce harm on the 75% live traffic before we call the class dead. `drop` already exists as a verdict; `foldLearningStages` keys on `To`, never enumerates causes — the new cause string is append-safe.
- Minimums met ∧ `liveHarm ≥ 1` → f′ satisfied; promotion then stands or falls on the existing legs.

**What stops the squat:** precisely that drop rule, and nothing else currently could. Proof the stall advisory is structurally insufficient: the canary stall arm fires only when `age > 12 && Canary.Outcomes < 10` (`learning_stages.go:490-500`, `learning_measure.go:55`) — a busy-but-vacuous canary (≥10 outcomes, zero liveHarm) **never even gets an advisory**, and `""` means stay forever, occupying the single R3 slot (`learning_canary.go:176`; queue starves on `shadow_queued`, `learning_stages.go:242-252`). Promote-condition-only f/g transplants replay's fail-closed posture into fail-open-forever. The drop is the price of moving the check to the expensive layer: replay-f was free to fail (kill at birth); canary-f′ must pay its way out of the slot.

## Q2 — g's reformulation: don't. The right denominator analysis retires it.

**f′ exact form** (integer floor, no division ever materializes):

```
liveHarm := m.Live.Rejects + m.Live.WeakRejects          // learningCohortStats, learning_measure.go:57-69
f′ ⇔ liveHarm ≥ 1                                        // evaluated only after paired minimums
```

Leg choice is forced by unit semantics: **prevention credit can only be measured on traffic the rule never covered.** The live leg is the only population where the harm class can appear as evidence. A canary-side reject is sign-ambiguous — a correct block the rule caused and rule-induced friction are indistinguishable in the current outcome vocabulary (`accept/reject/weak_reject`; `learning_measure.go` classify switch) — so no honest canary-side numerator exists. Auto outcomes do not transfer from replay-f (`learning_replay.go:623-624`): the measure excludes `auto_*` by the M17-F5 posture everywhere (fail-closed exclusion in `computeLearningMeasure`); consistency wins over class-parity. Human reverts: replay added `Reverts` to prevented harm (`learning_replay.go:630`); `computeLearningMeasure` tallies none. Acceptable asymmetry — document it; if parity is wanted later it is a mechanical extension of the fold, not of the gate.

**g: retire, document, do not transplant.** Three independent arguments:

1. **Dominated by construction.** The locked promotion leg already bounds canary weighted reject-rate ≤ live × 5/4, integer cross-multiplied (`learning_measure.go:461-470`, constants `:42-44`). Any canary-side "friction ≤ F×…" predicate with F ≥ 5/4 shares that numerator with a looser bound and can **never bind** — dead code shipped into a gate. With F < 5/4 it contradicts the locked posture. There is no F that makes a second predicate meaningful.
2. **Dishonest numerator.** Same sign-ambiguity as above: a canary-side friction count certifies a mixture of correct-blocks and rule-friction as one number. GLM's g made sense at replay only because replay's counters were already population-level proxies; the move to live injection is exactly where that approximation stops being harmless.
3. **The zero-denominator trap returns wearing a transplant mask.** Written as `canaryHarm·liveOutcomes ≤ 3·liveHarm·canaryOutcomes` (the only float-free, cohort-size-matched form — per the `float trap: 2×0.15 = 0.30000000000000004` precedent at `rules_audit.go:573-577`), `liveHarm = 0` forces `canaryHarm = 0`: structurally identical to the replay-f/g unpassability the amendment exists to remove. f′-ordering (liveHarm ≥ 1 required first) would mask it — i.e., the leg would be silently dead instead of loudly dead. Worse.

If the user insists g survives in name, the rate-normalized cross-multiplied form above is the only defensible integer statement — but the amendment text should then also state it is a **strictly looser superset of the 5/4 leg with zero behavioral effect**, which is a reason to not write the code. Also note the paired minimums run first, so `liveOutcomes ≥ 10` whenever either leg evaluates — the `bInj > 0` guard discipline (`learning_measure.go:407`) carries over by structure.

## Sharpest failure modes in the amended design

1. **Squat deadlock if shipped as promote-conditions-only** (the default reading of Option 1). f′ failing returns `""` = stay; single slot (R3); queue starves on `shadow_queued` forever; the stall advisory structurally cannot fire for busy-vacuous canaries. In a zero-reject project the *first* candidate would hold the slot permanently and the learning plane dies silently. The residence-bounded drop in Q1 is mandatory, not a refinement.
2. **Verbatim g-transplant reopens the zero-denominator trap in disguise.** Cheap form `canaryHarm ≤ 3·liveHarm` with `liveHarm ∈ {0,1,2}` is either unpassable-at-zero (the bug being removed) or vacuous; the cohort-size-matched form is a dominated twin of the 5/4 leg; and writing it in raw-count form over the 0.25/0.75 interleave (`learning_canary.go:74-88`, ordinal roll `:276`) punishes the minority cohort twice. Every variant fails on dominance, dishonesty, or duplication. Retire and document — otherwise auditors will forever read `g: pass` next to visible friction.
3. **Attribution-cheap f′ + non-freezing drops = churn-loop channel, and a f′-drop semantic the lock must say aloud.** f′ = "≥1 live reject in window" credits any candidate in any project with occasional churn — the efficacy screen is one bit; in genuinely calm projects it will *drop good procedural rules* (zero rejects for 3 epochs ⇒ measured vacuity, not defect). Both historical candidates were exactly such procedural rules. Meanwhile nothing freezes dropped texts (`learning_lint.go:96-124`), so the learner can re-propose the same text indefinitely, each loop costing 3 shadow epochs + a slot residence. Bounded and visible, but: fix §4.3 for `harmful_tuple` drops, and let the user rule separately on a repeat-vacuity window-freeze (deferable; not required for this amendment's correctness — required to be *named*).

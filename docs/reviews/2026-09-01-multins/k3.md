# A4 review — multi-namespace K8s Jobs (reviewer leg, independent)

Ground truth verified at ~/Projects/odo: `internal/ipc/k8s.go`, `internal/adapter/settings.go:184-265,+294`, `internal/ipc/protocol.go:528-540`, `gui/src/components/StatusBar.tsx:821-912`, `gui/src/jobs.ts`, lock + A2 + A3. Facts that drive verdicts below:

- `handleK8sStatus` calls `adapter.ReadSettings()` **per call** (k8s.go:84) → any pref shape change hot-applies next tick, no restart.
- Prefs.md is a flat `key: value` file; multi-values already live as comma-separated single strings (`review: a@x,b@y` via `set("review", …)`).
- `UpdateSettings` writes **non-empty strings only** (settings.go:221-265) → the off-state (empty) is not writable through the GUI today; `RemovePrefsKey` exists daemon-side but is not IPC-exposed. The bridge is Value-passthrough (bug-fix-epoch-53), so key *presence* is detectable at the `update_settings` JSON boundary.
- kubectl `-o json` items already carry `metadata.namespace` → the daemon can merge raw items and the GUI can group client-side; zero schema interpretation added daemon-side.
- A2-3 pinned settings as **global** (per-project override explicitly deferred) — multi-ns is a global scope, matching the requirement.
- Poll loop: `setInterval(() => void fetchStatus(), 5s)` with **no in-flight guard** (StatusBar.tsx:884-887); refetch-on-visibility-edge already exists.

## D1 — Input model: **ACCEPT Option A** (single key, comma-separated, parsed daemon-side), with fixes

A is the only shape that honors the prefs.md convention — multi-values are already comma-joined strings in one key (`review`), and B's "array" would serialize into the same flat file anyway, buying nothing but a second live key, a read-fallback precedence rule, and a migration that must not regress #140's write branch. A2-3's posture ("validation stays at the k8s_status handler — fail loud, not exec") maps cleanly: split → trim → validate each token against the existing `k8sNamespacePattern` → dedupe. C is rejected on requirement grounds: chip-on-primary-only silently hides the other namespaces from the always-visible surface — the exact lie-of-omission the A2-1 canon bans, and it makes chip and tab disagree about scope.

**Concrete recommendation:** keep `k8s_namespace: "default,lab"`. Daemon gains one pure function `parseK8sNamespaces(raw) ([]string, error)`: split on `,`, trim spaces (hand-edited prefs are supported), drop empty tokens, dedupe, per-token regex, hard cap **N ≤ 4**. Parse/overflow failure → `reason: "bad_namespace"` with `Detail` carrying the diagnostic (extends `Detail`'s doc one line from "stderr tail" to "diagnostic tail — stderr for exec-shaped, parse detail for pref-shaped"); GUI `reasonLabel` stays truthful. Empty string = off, unchanged. GUI gets exactly one new Settings row: free-text input with helper text "comma-separated; empty disables".

## D2 — kubectl strategy: **ACCEPT sequential N× `-n nsX` in one `k8s_status`**, with fixes; **REJECT `--all-namespaces` and parallel forking**

Sequential-in-one-call keeps the locked one-shot posture, produces one merged response (the only shape that gives per-namespace failure granularity, which D3 needs), and at the measured ~0.8s/ns costs 1.6s for 2 ns and ~3.2s at the N=4 cap — well inside the 5s cadence. `--all-namespaces` is a real escalation: cluster-list RBAC is broader than namespaced Roles (many clusters grant only the latter), it pulls every tenant's Job/Pod JSON over the wire every 5s, and a single call collapses failure granularity to total-failure only — incompatible with per-ns degradation. Parallel per-ns forks buy a latency haircut sequential already fits in budget, and multiply concurrent subprocesses the daemon serializes — not worth the concurrency surface for N≤4.

**Concrete recommendation:** loop namespaces sequentially in `handleK8sStatus`, each exec with its **own 10s CommandContext** (a shared budget lets a hung first ns starve later ones into a dishonest "timeout"). Response gains `namespaces: [{name, ok, reason?, detail?, job_count}]`; `jobs`/`pods` stay flat-merged raw passthrough (items self-identify via `metadata.namespace`); `truncated` becomes global over a 50-row merged cap — "first 50 of `Σjob_count`" stays a truthful popover line, and per-ns `job_count` lets the tab say which ns was cut. All-failed → top-level `available:false` with the first reason (existing shape); partial → `available:true` + per-ns entries.

## D3 — Chip semantics across ns: **ACCEPT summed badge; partial failure expressed by the existing contract per-namespace — no third chip state**

The chip face is locked counts-only, so `Jobs · N` sums active over *answering* namespaces and total unavailability (all ns down, or kubectl/cluster broken) collapses into the existing on-but-broken state with its reason — A2-1 untouched. Partial failure (one ns RBAC-denied) is neither off nor sensor-broken: the sensor answered with per-ns reasons. A2-1's axiom — "data may be absent, the reason may never be absent" — already covers this if the reason is carried per namespace; what's missing is only that a summed count over a subset would *silently* omit a configured scope. Fix is one honest marker, not a state machine.

**Concrete recommendation:** face = `Jobs · N` summed over ok namespaces; when any configured ns failed, append a warning glyph (⚠) and keep counts — never dim the whole chip (that hides good data) and never sum silently (that's the omission). Popover groups rows **by namespace** with a header per ns; failed namespaces render a degraded row inside their section: `lab — auth (forbidden: …detail)`, using the existing reasonLabel vocabulary. Title tooltip enumerates: `Jobs · 5 · lab unavailable (auth)`. Zero new color/state vocabulary beyond the glyph.

## D4 — Tab display: **ACCEPT flat table + namespace column; transient client-side filter; durable scope only in Settings; discovery pick-list DEFERRED**

A2-5 already locked a single Jobs table (name/phase/age/completions); adding a leading namespace column is the minimal honest extension, and per-ns section headers duplicate chrome for N≤4 while breaking cross-ns chronological scan. Default sort: namespace asc, then `creationTimestamp` desc (keeps `default`/`lab` visually grouped, newest first inside). A quick-switcher belongs in the tab but as a **transient, client-side visibility filter over the configured set only** — the data's already fetched, so it costs zero IPC/forks; making the tab a second scope *editor* would create two writers for the same truth (prefs.md), the exact dual-source failure the lock's thesis forbids. Discovery (`kubectl get namespaces` pick-list) genuinely de-risks typos, but `bad_namespace` fail-loud is the designed error path and A4 must stay an amendment — free text satisfies "GUI must let the user input namespace(s)" today.

**Concrete recommendation:** D5b locks: one flat sortable table, namespace as first column; Batches section inherits the same column. Tab header carries small toggle chips, one per *configured* namespace (session-memory only, never persisted, never editable there); all-on default; toggling never re-fetches. Settings remains the only scope writer. Discovery pick-list = named P1 follow-up amendment (`k8s_namespaces` list IPC, read-only `get namespaces -o json`, same exec posture; datalist/autocomplete in the Settings row) — shipped only after A4 proves out.

## D5 — Migration: **ACCEPT zero-migration under Option A; fix the empty-clear gap the old way has hidden**

`k8s_namespace: "lab"` remains a valid one-element list — parse is trivially backward compatible, `""` = off unchanged, and #140's `set("k8s_namespace", up.K8sNamespace)` branch persists comma lists verbatim, so `TestK8sPrefsRoundTrip` passes unmodified (extend it with a `"default,lab"` write/read case as the A4 pin). The real pre-existing gap the requirement forces out: `UpdateSettings` conflates *absent* and *empty*, so a Settings-panel save with a cleared field silently keeps the old value — the user could never turn the feature off from the GUI. Generic empty-means-clear is unsafe: `ModelPill` sends partial payloads (`{coding_model}`), which would read `K8sNamespace: ""` from Go zero values and wipe namespaces.

**Concrete recommendation:** presence-based clearing in the daemon's `update_settings` handler (bridge is already Value-passthrough): for `k8s_namespace` only — key absent → untouched (ModelPill path safe), key present with `""` → `RemovePrefsKey("k8s_namespace")`, key present non-empty → existing `set()` branch. SettingsPanel always sends the full struct, so clearing the row and saving turns the feature off; #140's non-empty round-trip is untouched. Hand-edited prefs remain fully supported either way.

## D6 — Poll cadence: **ACCEPT visibility-gated 5s at N≤4, with an in-flight guard; REJECT silent "first N" clamping and fan-out-on-open**

N×~0.8s typical fits the 5s tick; worst case is a hung cluster — with per-ns 10s deadlines a single call can take N×10s, and the current `setInterval(... void fetchStatus())` has **no in-flight guard**, so ticks would stack (today's single-ns worst case is benign at 10s; N×10s makes it a fork pile). Honesty also resolves the cap question: silently showing "first N" of an over-cap list is the omission pattern again — overflow must fail loud per D1. Fan-out on popover open buys nothing: the popover renders the ≤5s-old snapshot with `lastGoodAge` staleness display, and refetch-on-visibility-edge already fires when a folded chip reappears (fixtures pin "reappearing refetches immediately").

**Concrete recommendation:** keep 5s, visibility-gated. Add a guard in `fetchStatus`'s caller: skip a tick while a previous fetch is in flight (or an `inflight` ref checked in the interval callback). Effective cadence degrades honestly to call latency when a cluster hangs — slower truth beats fast wrong answers. Per-ns deadline stays 10s each; response carries per-ns entries so a 40s worst case still arrives *once*, fully reasoned, and the in-flight guard guarantees it never stacks.

## Locked summary (the paragraph I would sign)

A4 locks `k8s_namespace` as a comma-separated namespace list in the *existing* pref key — `""` = off, ≤4 entries, trimmed/deduped/per-token-validated daemon-side before any exec, overflow or bad charset answering `bad_namespace` with a parse diagnostic in `Detail` — with a single free-text Settings row as the GUI input and `update_settings` gaining presence-based clearing (key absent untouched, present-empty removes the line) so the off state is GUI-reachable without regressing #140 or partial senders. `k8s_status` executes N sequential `kubectl get jobs,pods -n nsX -o json` calls under one IPC (per-ns 10s CommandContext, argv-only, EnrichedEnv, 1KB stderr cap, never journaled) and returns flat-merged raw job/pod items — each carrying its own `metadata.namespace` — plus a `namespaces[]` entry per configured namespace (`name, ok, reason?, detail?, job_count`) and a global 50-row cap with truthful `truncated`; `--all-namespaces` and parallel forking are rejected (RBAC blast radius, payload, granularity; needless concurrency for N≤4 ~3.2s). The chip keeps counts-only over answering namespaces (`Jobs · N` + ⚠ when any configured ns failed; all-failed collapses into the existing visible-dimmed-unavailable state), the popover groups by namespace with per-ns reason rows, and the D5b tab renders one flat sortable table with a leading namespace column (ns asc, then newest first), batches inheriting the column, and a session-only client-side subset filter — scope is written only through Settings, preserving the single-truth rule. The 5s visibility-gated cadence stands with an added in-flight skip guard against stacked forks; migration is zero-code ("lab" is a one-element list), the round-trip test extends to multi-ns, and namespace discovery pick-lists defer to a named follow-up amendment after A4 ships.

# Deployment & Daemon Operations

- Deployment doctrine: replace the binary first (atomic cp-to-temp + `mv` inode swap), then kill the daemon — reversing the order resurrects the old binary because `ensure_daemon_running` relaunches from `<project>/odo` (main-epoch-31) (main-epoch-21) (UI-epoch-6)
- Both install paths are swapped together — `<project>/odo` and `~/.odo/bin/odo`; the shared path bootstraps daemons for projects lacking a local binary, and the inode swap is safe for running daemons (main-epoch-32) (UI-epoch-5)
- Verify new code is behaviorally live, not just replaced: `go version -m` vcs.revision, socket health via `nc -U`, and schema probes (`schema_version=3`, `diffs.goal` column) (main-epoch-21) (UI-epoch-11)
- Stale binaries were recurring and damaging: epoch-20's "new daemon built" claim was false (live binary still 5ec522bd+dirty at schema v2), causing #36's wrongful auto-reject under abolished one-vote-veto rules; a stale 10:26 binary also lacked `auto_land_started` instrumentation (main-epoch-21) (UI-epoch-4)
- Installed-app verification method: compare `/Applications/Odo.app` binary SHA-256 against the `target/release/bundle` artifact, check the running PID's `txt` mapping, confirm main HEAD contains the fix — definitively answers "is installed latest?" without rebuilding (UI-epoch-3)
- Mach-O grep is unreliable for GUI markers because Tauri compresses embedded resources; verify via `gui/dist` source markers + hashes instead (UI-epoch-5) (UI-epoch-6)
- Post-restart health evidence hierarchy: full `ps` over pgrep, PPID lineage (harness PPID = daemon PID proves orchestration), direct store queries, and journal WAL growth — log silence ≠ death (main-epoch-33)
- hermes daemon restarts kill its sessions, so each was user-gated since epoch-23; the loop auto-closed when hermes came up on the ab20b62 image after the user's own restart (main-epoch-31) (main-epoch-33)
- Bare `odo` CLI invocations can spawn unintended daemons inside worktrees; contain with absolute paths and timeout guards, and clean up self-created `.odo` skeletons (UI-epoch-6) (UI-epoch-5) (main-epoch-22)
- SIGQUIT immunity (`signal.Notify` + log + discard) was chosen over graceful wait because `srv.Wait` would hang shutdown up to ~24 min on in-flight panels; adopted after an unattributable external SIGQUIT killed a daemon mid-/panel (bug-fix-epoch-4)
- Orphan sweep runs first in `NewServer` recovery: non-control user_messages lacking `agent_done`/`agent_error` get an `agent_error{cause:daemon_restart}` closure so the GUI renders failure bubbles instead of hanging "resend" markers; the markers persist in history and do not indicate current failure (bug-fix-epoch-4) (UI-epoch-10)
- Panel progress heartbeat is memory-only (`panelProg`, never journaled, copied per poll to avoid an encode race) and drives the `· N/M back` spinner even if the GUI reopens mid-advisory (bug-fix-epoch-4)
- modernc.org/sqlite WAL-recovery SIGBUS is a recurring low-frequency hard crash; first remediation attempt is `_pragma mmap_size=0` in the connection string before any dependency upgrade (UI-epoch-10) (UI-epoch-11) (bug-fix-epoch-4)
- Go telemetry async-write races are eliminated by pinning `GOTELEMETRYDIR=$TMPDIR/odo-go-telemetry` for `go env` subprocesses — the per-user machine-wide shared default is concurrency-designed, so pinning restores that shape outside `t.TempDir` (main-epoch-26) (main-epoch-27)

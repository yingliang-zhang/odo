# Learner/Curator MoA Routing (R-W3)

- Flags learner_via and curator_via gate the OMP→moa migration; absent or omp keeps the wrapper byte-identical, and resolveDistillVia was generalized into one shared resolveVia(task, prefKey) covering distill, learner, and curator routes (moa-chain-epoch-1)
- Shared runMoaOneShot does a direct moa.Query with truncation fail-closed and deadline from moa.TimeoutForModel (moa-chain-epoch-1)
- Learner parse failure still returns the receipt because the request is already on the wire and auditable; transport failure carries none, and learner failure never fails distill (degrade semantics preserved) (moa-chain-epoch-1)
- Curator truncation and errors fail closed BEFORE any page rewrite, with manual and auto curate sharing the same branch; the fold marker uses learner_* prefixed keys to avoid colliding with distill's bare receipt keys (moa-chain-epoch-1)
- Learner/curator receipts use R-W1.5's client-side Result.RequestSHA16/RequestBytes rather than R-W2's prompt_sha16, via a new moaReceipt struct with journal(map, prefix) (moa-chain-epoch-1)
- GUI read timeouts were raised from the 1446s worst-case moa chain found in R-W1: DISTILL_READ_TIMEOUT 2100→3300s and CURATE_READ_TIMEOUT 660→1560s (moa-chain-epoch-1)
- ADR-0003 invariant 7 was reworded: cadence stays daemon-owned and direct-moa transport creates no model write path; invariant 1 untouched (moa-chain-epoch-1)
- Both flags ship opt-in only; no user decision is recorded on flipping the defaults from omp to moa (moa-chain-epoch-1)

# GUI UX Surfaces & Notifications

- UX-1 parked the TopBar action cluster at the right edge via margin-left:auto, with the pin popover and its error right-anchored — a left-anchored ~260px popover would overflow the viewport once the cluster parks right (verified: popover right edge 1370 of 1440) (bug-fix-epoch-48)
- odo advisories render amber (.bubble-advisory) instead of red and run headers exclude odo:true failures; deriveRuns deliberately treats advisories as non-terminal — no error row, no run closure — because a daemon advisory corresponds to no run's failure, and the daemon event type was left unmigrated (smaller diff, history not orphaned); a RunGroup holding only an advisory shows the unknown spinner rather than a fabricated error (bug-fix-epoch-53)
- The memory backoff surface derives per-layer latest-wins from journal events the GUI already holds (zero new IPC): curator backoff renders auto-curate paused with the next-eligible time (stale horizons hidden), distill reasons whitelist to idle/paused, transient/config/unknown stay hidden, and the daily-cap pause is deliberately not whitelisted since it already has its own chip (bug-fix-epoch-53)
- UX-3a notifications: agent_error fires a run-failed notification unless payload.odo === true (first GUI consumer of that flag) through a shared sendRunNotification channel with an __odoRunNotify e2e seam firing before the hidden-gate; the finished-flash error tint scans already-held poll events and leaves never-viewed/truncated workstreams as done — unknown is not faked as error (bug-fix-epoch-50)
- GUI derives from journal events, never daemon push: gate-drift detection folds the latest auto_land_blocked{gate_policy_drift} row within the daemon boot window in pipeline.ts, surfaced as an inline non-foldable StatusBar banner (inline rows avoid the App Esc-gate chain registration requirement) with banner width subtracted from the overflow computation (bug-fix-epoch-44)
- The design gate surfaces through the existing LoopChip + loop_ctl verbs (approve_design/amend_design/veto_design, which resolve the pending task themselves) rather than a new pending-gates list; EventPayload is a closed interface, so fixture extras no fold reads are dropped instead of widening the type (bug-fix-epoch-44)

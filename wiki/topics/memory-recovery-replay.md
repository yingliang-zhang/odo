# Memory Apply, Recovery & Replay

- Marker-first journaling: `applyResolvedBatch` journals an intent marker before performing writes, closing the crash window where a batch is applied but never marked; heal walks all stranded markers with per-layer newest-wins claims and is hooked into the consumed-refusal path and auto-gate sweep (main-epoch-39)
- Heal-vs-retry response contract: a retry whose heal actually completes the epoch's work returns `Applied: true`; a heal no-op (already persisted, bootstrap already healed, foreign state untouchable) keeps rejecting — reconciles legacy idempotency tests with crash-window pins (main-epoch-40)
- Project-level outbox (`memory_outbox.go`): boot-time replayer across all workstreams globally ordered by `store.Event.ID`; replays the original planner against the current file (idempotent rebase) rather than raw content or skipping; retract filter prevents resurrecting retracted rules; explanation-set gating (journal `after_sha` / outbox receipts) protects manual edits (main-epoch-42)
- `memMu` single-writer leaf lock (independent of `s.mu`/`acceptMu`): `applyResolvedBatch` re-folds the journal under lock for pending/consumed recheck — closes double-consumption and cross-workstream last-rename-wins for memory batches and pins (main-epoch-38)
- Replay semantics: newest receipt per layer wins; when an evaluation finds a layer's newest receipt landed, older open `heal_conflict`s for that layer retire via `heal_resolved{actor:"superseded", dismissed:true}` (bug-fix-epoch-7)
- Conflict retirement fires ONLY under project-wide fold context: `evalScope` gate lives inside `retireSupersededConflicts` so no callsite can forget it; lane-local evals (apply-retry, pin RMW, sweep) skip retirement unconditionally; legacy terminal-landed boundary receipts retire older conflicts under the same gate (bug-fix-epoch-8)
- Resolve freshness guard: conflict journalling records `disk_sha16_at_conflict`; resolve re-reads the file and refuses stale-body overwrite of newer receipts or hand edits, journaling the superseded dismissal (bug-fix-epoch-7)
- Project-wide consistency: `pending_counts` carries open heal-ledger rows as `(conversation_id, layer, receipt_seq)`; GUI Memory tab folds project-wide and resolve/dismiss routes by the owning conversation — archived lanes are actionable because delete is a status flip with no status predicate in the joins (bug-fix-epoch-7) (bug-fix-epoch-8)
- Store doctrine boundary: LEFT JOINs in `ListProjectEvents`/`ListHealLedgerRows` encode lane-row physical survival (migrations only UPDATE/ALTER); hard cascade-delete or whole-journal `rotate` is unrecoverable by construction — explicitly not overclaimed (bug-fix-epoch-7) (bug-fix-epoch-8)
- Live recovery rows carry verbatim per-rule added lines (previously only body + SHAs); `memoryMergePlan` reuses the receipt's recorded line, falling back to `reaffirmed: 1` only when absent (bug-fix-epoch-7)
- Paged boot replay: `replayJournalReadPage = 512` keyset pagination (`e.id > ? ORDER BY id LIMIT ?`) with one per-lane fold carrying all order-dependent state across page boundaries (streaming reduce, not accumulation) (bug-fix-epoch-11) (bug-fix-epoch-12)
- `proposeByEpoch` growth bounded: superseded epochs are pruned on fold apply while the current epoch is retained for same-epoch retry pairing (bug-fix-epoch-12)
- Swept consumed batches repair live: `sweepPendingBatch` takes `memMu`, re-reads the journal fresh, and replays a failed-write marker immediately instead of waiting for the next apply or restart (bug-fix-epoch-8)
- Pins are journal-first with heal-before-RMW; reaffirm is set-to-epoch not a counter, so double-apply risk is archive duplicates/ordering and marker-first journaling closes the class regardless (main-epoch-39)

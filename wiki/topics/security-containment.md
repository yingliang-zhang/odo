# Daemon Security & Path Containment

- Canonical projectRoot is the final trust anchor: the guarded read verifies the resolved dir stays inside the project and rejects symlinked root nodes (.odo, wiki, wiki/topics) themselves; the write side carries the same guard, and containment violations degrade to absent/vanished semantics rather than new error faces — global ~/.odo dotfiles are deliberately outside the threat model (main-epoch-34)
- Skill paths resolve through guardedBase, and delete gained the same guardProjectWritePath the update path had — a symlinked .odo/.odo/skills chain otherwise degrades the whole project skill scope to absent; skill files cap at 64KB with oversized files skipped (continue, not break) so one large skill never blocks smaller relevant ones (main-epoch-38)
- Loop artifacts fail closed at both read sites via loopArtifactBody guarded containment plus a per-field sha16 comparison — tampered, escaped, or symlinked findings/design_lock artifacts never execute (main-epoch-38)
- /preview validation is Go-side because capture runs through the Playwright CLI: per-hop redirect validation with final-URL capture (and a final_url audit field), unreachable hosts failing fast at probe; JS/meta-refresh redirects remain the documented v1 boundary (main-epoch-30)
- /preview remote fetches run through an in-process loopback-only filtering proxy env-injected into the Playwright child — off-loopback requests are logged and denied before dial — with Playwright pinned to the lockfile version (1.62.1) and an explicit setup phase (main-epoch-32)
- Bounded reads everywhere: the loop task file gets an os.Stat size pre-check with the cap enforced during read (before allocation), and large-file previews stream through os.Open + io.LimitReader(cap+1) instead of ReadFile-then-slice (main-epoch-38)
- Accept protects user work: patch-own dirty paths (staged/unstaged/untracked) refuse before apply — rollback previously wiped the user's uncommitted changes — and the refusal is deliberately not wrapped as errBaseStale because user dirt requires human triage, not another auto-revise cycle hitting the same refusal (main-epoch-28)
- Staged-only edits are refused before adjudication via git.IndexEditsBeyondHEAD (real index vs HEAD stage-0 compare) so a divergent index is never clobbered by git add (main-epoch-32)
- Already-landed detection compares bytes (temp-index post-image vs worktree hash-object per file) so stray edits are never swept into an accept commit, and the identical-content rescue runs before the dirty-path refusal (main-epoch-30)
- Supply-chain and memory paths stay hard-blocked pre-panel as terminal protected_path: a one-line lockfile dependency change is an RCE vector diff review structurally cannot judge (main-epoch-24)

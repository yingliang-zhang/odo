# Auto-Land Pipeline Governance

- Terminal `auto_land_blocked` diffs never auto-retry; the human Accept click in the GUI Review inbox is the only unlock (precedent chain #41/#42/#45/#46/#48/#49), and the store staying `pending` is what keeps that channel open (main-epoch-41)
- Accept-on-flake doctrine: when identical patch bytes already passed full verify and one spec fails under load (green in isolation), a re-run has zero information gain — accept instead of burning another ~8.5-minute verify+panel round (main-epoch-29)
- Resolve superseded diffs in order: reject the older diff first — recover-pending-diffs re-fires panels on every daemon restart while a diff lacks a terminal verdict — then accept the superset (main-epoch-41)
- Verify output is persisted to `.odo/verify/<label>-<ts>.log` (1 MB tail cap, pruned to newest 32) with the journal pointer appended after capping so it can never be truncated away (main-epoch-36)
- capDetail truncation is tail-biased (prefix marker + rune-safe 4 KB cut) so `--- FAIL:` lines survive journal blocked details — head-trimming repeatedly blinded failure identification until a same-bytes re-run recovered it (main-epoch-26)
- Reject destroys the candidate worktree; the archived `.diff` is the sole survivor — recovery is a clean `git apply` of the backup, and retirement now snapshots a rescue diff before removal so reviewed bytes are never the only copy (main-epoch-35)
- Verify budget is 30 m: the 15 m default was consumed by the GUI segment alone (verify_ms=952493); the infra signature is all-executed-segments-green plus budget exhausted, distinct from a real red segment (bug-fix-epoch-55)
- Dirty-path refusals are deliberately NOT wrapped as `errBaseStale` — wrapping would drive the auto-revise loop to regenerate a patch hitting the same refusal; user dirt requires human triage, and the M20 identical-content rescue is ordered before the refusal so unstaged identical edits still land (main-epoch-28)
- Diffs touching Tier-0 gate files auto-land blocked with `gate_core_path` by design — the block is expected, not a defect, and landing requires the human Accept click (bug-fix-epoch-57)
- The daemon owns verification: agents stage only (zero commits, no local gate runs) and the drain (`git add -A` -> ExtractDiff -> InsertDiff) extracts at run end; intake verify re-runs the full suite on the final bytes (bug-fix-epoch-58)
- Unscoped `git add -A` in the main checkout is P0-forbidden (it would sweep unrelated user changes); accept-time staging keeps the patch-path-union scope but filters ghost paths — renames pre-staged by `git apply --3way` exist in neither worktree nor index, which previously made StagePaths fatal (bug-fix-epoch-53)
- Verify determinism fixes land on main so the next diff is not doomed: `TestPlaywrightBrowsersDir` scrubs `PLAYWRIGHT_BROWSERS_PATH` via `t.Setenv`, and `go env` subprocesses pin `GOTELEMETRYDIR` under `$TMPDIR` to kill the telemetry async-write race (main-epoch-26)
- Deployment follow-through: replace binaries atomically (cp-to-temp + mv at both `<project>/odo` and `~/.odo/bin/odo`) BEFORE killing the daemon — `ensure_daemon_running` would otherwise resurrect the old image — then verify `vcs.revision == HEAD` and socket health (main-epoch-41)

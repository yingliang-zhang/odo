# Auto-Land Pipeline & Diff Governance

- Diffs are content snapshots: run-end drainRun extracts worktree-vs-HEAD into .odo/diffs/<run>.diff (append-only, sweeper-exempt archive); rebases refresh via UpdateDiffBaseSHA, and folding small stale-test fixes into an existing green snapshot beats a separate hotfix round-trip (main-epoch-10)
- Verify observability has two tiers: full gate output persists to .odo/verify/<label>-<ts>.log (1MB tail cap per file, prune to newest 32) with the pointer path appended AFTER capping so it can never be truncated away (main-epoch-36)
- capDetail keeps a rune-safe 4KB tail (head-trim abandoned) so '--- FAIL' lines survive in blocked journal rows; the old head-trim forced blind same-bytes reproductions just to name the failing test (main-epoch-26)
- Terminal blocked states (verify_failed, panel verdicts) never auto-retry, so manual GUI Accept is the only unlock — precedent chain #41/#42/#45/#46/#48/#49/#52, including sha-stale blocks where the old block row is bound to a pre-repack patch sha (main-epoch-41)
- Invariant: agents never write memory — memory paths (wiki/, .odo/) and supply-chain manifests/lockfiles are the only hard blocks, refused fail-fast at registration (advisory naming paths + salvage patch kept) and again at accept for every actor including a human click; gate-source files are not blockers, only panel risk annotations requiring unanimity (main-epoch-24)
- Reject path rescues work: retiring a rejected run snapshots the live worktree delta to .odo/diffs/<run>-rescue.diff when it differs from the archived patch (archived bytes never rewritten), because reject destroys the candidate worktree (main-epoch-36)
- Boot recovery dedupes against terminal journal rows (blocked reasons other than panel_infra, auto_panel verdict rows, auto_revise_round); panel_infra re-fires by design — infra failure is not a verdict — and a journal read failure abandons the whole pass fail-closed (UI-epoch-9)
- recoverPendingDiffs excludes loop-owned seeds (seed recovery is the loop pipeline's own job) (main-epoch-16)
- Auto-revision chains: reject a strict-superset origin before accepting its product so a daemon restart cannot re-fire the stale diff's recovery window; rescueResolvedWorktree snapshots pre-retire, so rejection is safe (main-epoch-41)
- Diffs over 64KB cannot enter the auto-revise repair chain ('no silent truncation, ever', cap pinned by settle_test); manual Accept is the only unlock at that size (main-epoch-33)
- Regenerating patch bytes before a manual accept is safe only when the diff never reached a panel (no patch_sha16 attestation binding exists); panel-reviewed bytes must instead repack to a new sha (main-epoch-22)
- Accept guards refuse apply when patch-own paths carry staged/unstaged/untracked user content (names paths, diff stays pending, refusal NOT wrapped as errBaseStale since user dirt needs human triage); ProbeAlreadyLanded reverse-apply check runs first so identical content lands via bookkeeping, not rejection (main-epoch-28)
- Staged-only edits are protected by git.IndexEditsBeyondHEAD (real index vs HEAD stage-0 compare) with a unified refusal before adjudication — the accept path's git add no longer clobbers a divergent index (main-epoch-32)
- runVerify executes under a scratch HOME with scrubbed env; GOTELEMETRYDIR is pinned under $TMPDIR (kills the go-telemetry async-write cleanup race) and PLAYWRIGHT_BROWSERS_PATH is explicitly cleared in the browsers-dir test (main-epoch-26)
- verify_unconfigured is fail-closed by design — no auto-created .odo-verify because a daemon committing its own verify oracle is exactly what the supply-chain gate blocks; instead a once-per-project-per-daemon-lifetime advisory fires at the block point with toolchain-aware guidance (main-epoch-12)
- Advisory adjudication rounds locked the semantics: 'configured' means committed in HEAD (git show HEAD:.odo-verify via ShowHEADFile), a three-state None/Partial/Ready scope check for scoped configs, and the debounce claim serialized under verifyAdviseMu (journal-first-in-lock) so a journal failure releases the claim for retry (main-epoch-13)
- M20 settlement: auto-land is armed by default ('off' remains kill-switch; zero review models silently unarms), panel reject auto-rejects with an evidence row, base_stale auto-revises at current HEAD via the ladder, and GUI accept/reject survives only as a triage/override valve, not the required path (main-epoch-8)
- The M20 arming gate reads 'review:' from prefs.md in process HOME, so verify's scratch HOME made an isolation-less test environment-dependent — the latent defect surfaced only when that diff was the first to actually traverse verify after the gate landed (main-epoch-25)
- Epoch-42's own diff was rejected at registration for touching protected wiki/topics/memory-distill.md and retired whole; the full patch is preserved at .odo/diffs/6a8d8993-68af79915939.diff pending wiki-hunk strip and resend of the Go/GUI work (main-epoch-42)
- Externally landed content reconciles via one atomic transaction: store status flip to accepted + a human review_action row naming head_sha — neither accept (stale base would re-apply and clobber user edits) nor reject (inverted semantics, pollutes autonomy stats) (main-epoch-8)
- When the GUI itself is unclickable, human accept/reject works over the daemon unix socket — handleDiffAction has no pipeline lock, only acceptMu and status checks (UI-epoch-10)
- Mixed-technology diffs run ALL applicable .odo-verify matches (not first-match-wins), with dependency provisioning shared across the autoLand and loop call sites (UI-epoch-5)

# Auto-Land Pipeline & Diff Governance

- Three-round panel rule: rounds 1–2 require unanimous accept (any reject leg auto-rejects, fail-closed); only the terminal round 3 passes on a strict-majority valve that itself fails closed on any truncated leg (main-epoch-21)
- Diverged panels (panel_mixed) enter the repair ladder instead of instant auto-reject; divergence persisting past the round cap is decided by strict majority (>½ accepts), else the chain suspends for human review (main-epoch-19)
- A lone or same-family dissent suspends instead of killing: exactly one reject leg (or all-same-family rejects) journals panel_minority_reject, keeps the diff pending, and allows one bounded re-panel on daemon restart; only ≥2 rejects from ≥2 distinct model families auto-reject (bug-fix-epoch-17)
- Model family derives from the bare model id with the provider tag stripped — one model behind two provider labels is one family, so label diversity is never mistaken for model diversity (bug-fix-epoch-17)
- auto_land_blocked{verify_failed} is terminal — the daemon never retries; GUI Review-inbox Accept is the only unlock, with gate-source manual accepts carrying precedent #41/#42/#45/#46/#48/#49 (main-epoch-41)
- Manual-accept evidence discipline: prove the block spurious by same-bytes reproduction (archive sha16 match, payload path attribution, isolated spec reruns) — a green reproduction makes re-running verify+panel zero-information-gain and re-exposes panel risk (main-epoch-36)
- Review objective anchoring: the diff's goal is stored at InsertDiff (schema v3 goal column, atomic v1→v3/v2→v3 migrations) instead of re-scanning the session's latest human message, which mis-killed diffs on unrelated later notes (main-epoch-18)
- Reject a superseded auto-revise predecessor before accepting its successor, closing the recovery-race window where a daemon restart re-fires the pending predecessor against the just-accepted product (main-epoch-41)
- panel_infra is the only non-terminal blocked reason — its designed resolution is daemon restart re-firing the pipeline through recover-pending-diffs (main-epoch-17)
- Verify output persists to .odo/verify/ logs (1MB tail cap per file, pruned to newest 32) with the journal pointer appended after capping so it can never be truncated away; success paths persist too (main-epoch-36)
- capDetail is tail-biased (rune-safe 4KB keep-the-end with an earlier-truncated prefix) so --- FAIL lines survive in journal blocked rows — head-trimming made verify failures undiagnosable across #39/#40/#47 (main-epoch-26)
- Oversized repair prompts get a needs-based settle digest instead of cap-chasing: above a 128KB trigger the revise prompt carries a per-file stat block plus full hunks of only feedback-named files plus an elision trailer pointing at the on-disk patch; the 256KB hard cap stays as backstop on the digested input, and the named set is intersected with validated patch paths so files are never smuggled in (bug-fix-epoch-29)
- Repair chains are permanently closed above the hard diff-size cap (settle.go, 'no silent truncation, ever') — at that size Manual Accept is the only unlock path (main-epoch-33)
- Rejecting a diff deletes its candidate worktree, leaving the archived .diff backup as the sole survivor — recovery means dry-check plus clean re-apply of the backup onto a fresh worktree (main-epoch-35)
- rescueResolvedWorktree snapshots uncommitted deltas to a <run>-rescue.diff before worktree retirement (reject and accept share the retire path) and never rewrites the reviewed patch bytes (main-epoch-36)
- Patches are regenerated per drain semantics (git add -A && git diff --cached HEAD) before accept so landed bytes include late fixes — safe only when the diff never reached the panel, since panel attestation binds patch_sha16 (main-epoch-22)
- Manual land (git apply + commit + ledger_correction journal row) is the recovery path when a split verdict terminalizes a diff already verify-proven on identical bytes; store statuses are corrected by journal rows, never silent DB mutation (main-epoch-27)
- Orphaned commits stranded on deleted session worktrees are recovered by cherry-pick onto main plus a second correction declaring the prior correction's premise invalid (main-epoch-20)
- Block-reason precedence: run-state evidence (run_errored, tainted verdict) is checked before config advisories like single_judge_panel, so errored runs never burn the once-per-lifetime advisory quota (main-epoch-18)
- Panel findings on cap/digest behavior were closed with new test pins rather than code changes — conservative over-elision is the sanctioned direction because the trailer always points at the full source (bug-fix-epoch-30)

# Deployment & Daemon Lifecycle

- Deploy order is replace-then-kill: atomically swap binaries (cp-to-temp + mv) at both <project>/odo and ~/.odo/bin/odo before killing the daemon, or ensure_daemon_running resurrects with the old binary (main-epoch-31) (UI-epoch-6) (main-epoch-21)
- Post-restart verification: go version -m vcs.revision == HEAD at both install paths, socket health, and schema expectations (e.g. schema_version=3 with diffs.goal) as behavioral proof the new code is live; log silence is not death (main-epoch-21) (main-epoch-41) (main-epoch-33)
- Stale daemons misjudge diffs under abolished rules (#36 rejected under the retired one-vote-veto by a #27-era binary) and cannot enforce daemon-side fixes until restarted (#52's heal semantics) — rebuild/swap/restart is part of landing, not an afterthought (main-epoch-21) (main-epoch-41)
- Odo.app deploys via tauri cold build + ditto replace of /Applications/Odo.app; Mach-O grep is unreliable for bundle verification (Tauri compresses embedded assets) — verify via gui/dist markers plus sha256 (UI-epoch-5) (UI-epoch-7)
- Graceful daemon exit SIGKILLs in-flight agent requests (main.go:193), so restarts lose in-flight panels/advisories and stamp orphan resend bubbles that persist in chat history without indicating current failure (main-epoch-41) (bug-fix-epoch-4) (UI-epoch-10)
- hermes-agent daemon state is decoupled from odo's lifecycle (own store and capture file at ~/.hermes), but restarting it kills its sessions — a user decision deferred across many epochs until done in epoch-33 (UI-epoch-11) (main-epoch-23) (main-epoch-33)
- Bare `odo help`/`odo` CLI probes can spawn unintended daemons, and a bare run in a worktree bootstraps a skeleton .odo directory there (UI-epoch-6) (main-epoch-22)
- Recurring modernc.org/sqlite SIGBUS (WAL mmap recovery crash) is the only observed unexpected daemon death; candidate remediations are _pragma mmap_size=0 (one-line) before attempting a dependency upgrade (UI-epoch-10) (bug-fix-epoch-4)

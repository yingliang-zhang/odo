# Memory Distillation & Auto-Distill

- Marker-first recovery: `applyResolvedBatch` journals the intent marker BEFORE performing writes, closing the applied-but-never-marked crash window; heal walks ALL stranded markers (multi-marker, newest-wins per layer) and also runs on the consumed-refusal path and in the auto-gate sweep (main-epoch-39)
- Consumed-branch contract: a heal that actually completes the epoch's work this call returns `Applied: true`; a heal no-op (already persisted/bootstrap-healed/foreign state) keeps rejecting — this reconciles the legacy idempotency test with the crash-window pin (main-epoch-40)
- Project-level outbox (`memory_outbox.go`): boot-time replayer across all workstreams globally ordered by `store.Event.ID`; replays the planner against the current file (idempotent rebase onto foreign state) rather than skipping; applied/conflict accounting via `receipt_seq` (main-epoch-42)
- Explanation-set gating: a memory file hash is writable only if explained by journal `after_sha` values or outbox receipts — chosen over hash-equality so manual file edits are neither clobbered nor resurrected (main-epoch-42)
- Auto-distill spawns, timer callbacks, and `recoverPendingDiffs` fan-out live under `Server.wg`; `rig.stop` drains in-flight work (~3.8s measured) — this killed `database is closed` writes after TempDir cleanup (main-epoch-42)
- Pins: journal-first write plus heal-before-RMW; reaffirm is set-to-epoch (not a counter), so marker-first journaling closes the double-apply class (main-epoch-39)
- `memMu` single-writer leaf lock: `applyResolvedBatch` re-folds the journal under lock for the pending/consumed recheck — closes double-consumption and cross-workstream last-rename-wins for batches and pins (main-epoch-38)
- The file-write-before-journal crash window is deliberately kept: `normalizeRule` dedupe makes replay idempotent, so the benign window stays; the real gap was the missing single-writer lock (main-epoch-38)
- Empty-window guard judges by `!unownedFoldGrowth(events, firstSeq-1)`, so pure wiki-commit telemetry windows count as empty and never self-trigger distills (main-epoch-11)
- Memory/wiki auto-adjudication: `distillCore` is the single funnel — gate + propose before the marker, auto-apply after; wiki changes auto-commit at distill end via `commitWiki` emitting `memory_update{layer:wiki}` (main-epoch-11)
- Daily-cap feedback loop fix: on first cap hit per day journal exactly one `memory_update{cause:"cap_suspended_until"}` and nothing further; a single timer aims at the earliest quota release; scheduler bookkeeping rows are excluded from both the eligibility window and render (production had 3786→3819 events of pure self-amplifying scheduler noise) (bug-fix-epoch-9, bug-fix-epoch-10)
- Cap-hit serialization: check→journal→cache is serialized across concurrent `runAutoDistill` goroutines (exactly one suspension row and one timer, proven under `-race`); the resume timer re-arms or re-suspends on lookup failure instead of silently dying (bug-fix-epoch-10)
- Render/count split is load-bearing and must not reconverge: `foldExcludedMemoryUpdate` (render) excludes only scheduler bookkeeping; `windowExcludedMemoryUpdate` (eligibility counting) additionally excludes the heal/recovery cause family, gated to the replay-layer family only (bug-fix-epoch-11, bug-fix-epoch-12, main-epoch-42)
- Boot replay is paged: `replayJournalReadPage = 512` keyset pagination over `ListProjectEventsPage` (the only listing API — `ListProjectEvents` was deleted; `limit <= 0` is a hard error, never silently unbounded); a per-lane fold streams state across page boundaries; superseded epochs are pruned from the proposal map on fold apply (bug-fix-epoch-11, bug-fix-epoch-12)
- Fold commit atomicity: `store.CommitFold` performs epoch bump + marker in one SQLite transaction (main-epoch-23)
- `ListEvents` narrowing: a no-pin marker falls back to a full-history scan (`firstSeq=0`) so the sweep still rescues pre-pin legacy batches; pinned logs get the narrowed fold window (main-epoch-23)

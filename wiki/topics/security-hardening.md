# Security Hardening & Containment

- Canonical projectRoot is the final trust anchor: guards verify the resolved path stays inside the project and reject symlinked root nodes (.odo, wiki, wiki/topics) themselves; the write side carries the same guard, not just reads (main-epoch-34)
- Containment violations degrade to vanished/absent semantics — no new error faces; global ~/.odo files stay outside the threat model to preserve legitimate dotfile symlinks (main-epoch-30)
- AGENTS.md generation reads memory.md/pins.md through readWithinDir containment with Lstat symlink refusal on writes for daemon-owned files (main-epoch-32)
- /preview SSRF posture: capture goes through the playwright CLI (no browser-layer interception possible), so validation is Go-side per-hop redirect validation plus final-URL capture; JS/meta-refresh redirects are a documented v1 boundary (main-epoch-30)
- /preview was hardened with a loopback-only filtering proxy env-injected into the Playwright child — off-loopback requests are logged and denied before dial (main-epoch-32)
- Playwright is pinned to the lockfile version (1.62.1) with an explicit setup phase — never unpinned playwright@^ remote code (main-epoch-34)
- Accept paths refuse when patch-own paths carry staged/unstaged/untracked user content (git.DirtyPaths precheck at both apply sites); the refusal names paths, keeps the diff pending, and is not wrapped as errBaseStale — human dirt needs human triage, not an auto-revise cycle (main-epoch-28)
- Staged-only edits are protected by git.IndexEditsBeyondHEAD (real index vs HEAD stage-0 compare) so adjudication never clobbers a divergent index (main-epoch-32)
- Already-landed detection is per-file byte comparison via a temp-index post-image vs worktree hash-object — whole-file CommitPaths would absorb stray edits (main-epoch-30)
- Skill-scope chains resolve through guardedBase with guardProjectWritePath on update AND delete (delete previously lacked it); a symlinked .odo degrades the project skill scope to absent (main-epoch-38)
- Loop/task file reads anchor at resolvedRoot with stat prechecks, and readWithinDir's post-hoc length check was replaced by a capped reader enforcing the limit during the read, before allocation (main-epoch-42)
- Loop artifacts fail closed on tamper: loopArtifactBody does guarded containment plus <field>_sha16 comparison; tampered/escaped/symlinked findings and design_lock artifacts are rejected at both read sites (main-epoch-38)
- Skill scan enforces a 64KB per-file limit and injection uses continue so one oversized skill never blocks smaller relevant ones (main-epoch-38)
- Large reads stream: the >512KiB preview path uses os.Open + io.LimitReader(cap+1) rather than os.ReadFile-then-slice (main-epoch-28)
- Explicit non-guards: diff PathOnDisk (adapter/test-generated, outside the committable threat model) and user-supplied vision attachment paths are deliberately unguarded (main-epoch-34)

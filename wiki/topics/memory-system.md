# Memory System & Distill Reliability

- Marker-first recovery: applyResolvedBatch journals an intent marker before any write, closing the crash window where a batch is applied but never marked; the heal walks all stranded markers (multi-marker, per-layer newest-wins claims) and must also run on the consumed-refusal path and the auto-gate sweep, or a distill right after a crash retires the marker unhealed (main-epoch-39)
- Heal semantics reconciliation: a heal that actually completes the epoch's work returns Applied: true; a no-op heal (already persisted / foreign state untouchable) keeps rejecting — this reconciles the legacy idempotency pin with the crash-window pin the auto-revise round had left conflicting (main-epoch-40)
- Project-level outbox (memory_outbox.go): a boot-time replayer across all workstreams, globally ordered by store.Event.ID, re-runs the original planner against the current file (idempotent rebase) instead of skipping foreign-state intents; a retract filter prevents resurrecting retracted rules (main-epoch-42)
- Explanation-set gating: a memory file hash is writable only if explained by journal after_sha values or outbox receipts — manual edits are neither clobbered nor cause rule resurrection; chosen over hash-equality for exactly those two properties (main-epoch-42)
- memMu is a single-writer leaf lock (touching neither s.mu nor acceptMu); applyResolvedBatch re-folds the journal under lock for a pending/consumed recheck, closing double-consumption and cross-workstream last-rename-wins for batches and pins (main-epoch-38)
- AGENTS.md carries only the stable protocol (project rules + todo contract) — dynamic memory/pins copy blocks were removed so the model sees exactly one receipted copy (main-epoch-38)
- Auto-distill goroutines, timer callbacks, and the recoverPendingDiffs fan-out are wrapped into the Server waitgroup so rig.stop drains in-flight work — previously distill writes hit closed stores after TempDir teardown (main-epoch-42)
- Agents never write memory (invariant 1): the accept layer refuses memory paths for every actor including a human Accept click; memory/wiki content belongs to the daemon's distill/curate/commitWiki pipeline (main-epoch-24)
- The auto-learner's zero-applied-rules disable-rationale was very likely the parseVerdict parsing bug, not genuine zero-yield — the re-enable decision remains pending, and no post-fix panel review has yet demonstrated a first accepted memory_apply (bug-fix-epoch-43)

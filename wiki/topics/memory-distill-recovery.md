# Memory Distill, Replay & Recovery

- Marker-first journaling: applyResolvedBatch writes an intent marker before any file write; the heal runs on entry, walks ALL stranded markers with per-layer newest-wins claims, and also runs on the consumed-refusal path and in the auto-gate sweep (main-epoch-39)
- Idempotent-retry contract: a retry whose heal actually completes the epoch's work this call returns Applied:true; a no-op heal (bootstrap already healed, foreign state untouchable) keeps rejecting — reconciling the legacy idempotency test and the crash-window pin (main-epoch-40)
- Project-level outbox: a boot-time replayer across all workstreams, globally ordered by store.Event.ID, re-runs the original planner against the current file (idempotent rebase rather than skip), with retract filters, two-pass project-wide collection, and explanation-set gating (a hash is writable only if explained by journal after_sha values or outbox receipts) (main-epoch-42)
- memMu is a single-writer leaf lock (not s.mu/acceptMu); applyResolvedBatch re-folds the journal under lock for pending/consumed recheck, closing double-consumption and cross-workstream last-rename-wins for batches and pins (main-epoch-38)
- AGENTS.md carries only the stable protocol envelope (Project Rules + odo-todo contract); dynamic memory/pins copy blocks were removed so the model sees exactly one receipted copy (main-epoch-38)
- Contradiction detection is advisory-only: candidates journal contradiction_candidate rows and never filter recall; retraction happens via curator supersede or the odo retract CLI (mandatory once auto-retract was demoted) (main-epoch-14)
- D4 memory authority: user.md batches are scope-held for human apply (zero panel spend), learner flags are consumed as verbatim evidence with LLM-free vetting, retract intents ride the panel gate, and odo memory revert restores a rebuilt pre-image with evaluate-time authority checks so replay can never restore over a human revert (bug-fix-epoch-19, bug-fix-epoch-20)
- The render/eligibility split is load-bearing: heal rows render byte-identically in the distill prompt but are excluded from window eligibility and window_bytes; two predicates (foldExcludedMemoryUpdate vs windowExcludedMemoryUpdate) must not reconverge (bug-fix-epoch-11, bug-fix-epoch-12)
- Boot replay is paged (keyset pagination, 512 rows/page) and ListProjectEventsPage is the only listing API; limit <= 0 is a hard error so the unbounded enumeration path cannot silently resurrect (bug-fix-epoch-11, bug-fix-epoch-12)
- Memory/wiki auto-adjudication: distillCore is the single funnel (gate+propose before the fold marker, auto-apply after it); wiki changes auto-commit via commitWiki emitting memory_update{layer:wiki}; an empty window is judged by unownedFoldGrowth so pure bookkeeping telemetry no longer fools the nothing-new probe (main-epoch-11)
- The two auto-review paths differ fundamentally: diff auto-land hard-depends on a committed .odo-verify (fail-closed), while the memory/wiki auto-gate has zero verify dependency and gates only on review models (main-epoch-12)
- Learner instrumentation ships before gate changes: batch_superseded journal rows, per-epoch accepted/rejected ledger lines, and a deploy-staleness WARNING (binary mtime >5min behind HEAD) (main-epoch-14)

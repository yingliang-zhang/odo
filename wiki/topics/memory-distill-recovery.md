# Memory Distill, Journal & Crash Recovery

- Marker-first recovery for memory apply: applyResolvedBatch journals an intent marker before performing writes, closing the crash window where a batch is applied but never marked; heal walks ALL stranded markers (multi-marker, per-layer newest-wins claims) and runs on the consumed-refusal path and the auto-gate sweep (main-epoch-39)
- Heal semantics contract: a retry whose heal actually completes the epoch's work this call returns Applied:true; a heal no-op (already persisted/bootstrap-healed/foreign state) keeps rejecting — reconciling TestUserMemoryIdempotency with TestApplyMemoryCrashWindowHeals (main-epoch-40)
- Project-level outbox (memory_outbox.go): a boot-time replayer across all workstreams, globally ordered by store.Event.ID, replays the original PLANNER against the current file (idempotent rebase of intents onto foreign state) rather than replaying raw content or skipping; a retract filter stops resurrecting retracted rules (main-epoch-42)
- Explanation-set gating protects manual edits: a memory file hash is writable only if explained by journal after_sha values or outbox receipts (mem/pins_after_sha) — chosen over hash-equality so manual edits are neither clobbered nor cause rule resurrection (main-epoch-42)
- memMu is a single-writer leaf lock (does not touch s.mu/acceptMu); applyResolvedBatch re-folds the journal under lock for pending/consumed recheck, closing double-consumption and cross-workstream last-rename-wins for both memory batches and pins (main-epoch-38)
- Auto-distill spawns, timer callbacks, and recoverPendingDiffs fan-out are wrapped in the Server waitgroup so in-flight work cannot write wiki/journal after TempDir cleanup and store close (raced 1-in-3 as 'database is closed'); rig.stop drains in-flight work (main-epoch-42)
- Memory/wiki panel auto-adjudication funnels through distillCore: gate + propose before the marker, auto-apply after the marker (so unownedFoldGrowth needs no change); wiki changes auto-commit at distill end emitting a memory_update{layer:wiki} event (main-epoch-11)
- Empty-window guard redefined as !unownedFoldGrowth(events, firstSeq-1) — pure bookkeeping (e.g., wiki-commit telemetry) windows count as empty and do not self-perpetuate distill (main-epoch-11)
- Auto-distill daily-cap circuit breaker: on first cap hit journal ONE memory_update{cause:cap_suspended_until} and arm a single timer at the earliest quota release; scheduler bookkeeping rows (scheduled/skipped/cap_suspended_until) are excluded from window eligibility (they previously measured and grew themselves, 3786→3819 pure-noise events in production); resume fires exactly one normal scheduled row — no catch-up storm (bug-fix-epoch-10)
- Heal-row render/eligibility split is load-bearing: foldExcludedMemoryUpdate (render — keeps heal rows in the distill prompt as real memory history) and windowExcludedMemoryUpdate (count — additionally excludes recover/heal_* boot-recovery bookkeeping, which embeds KB-sized stranded_body payloads inflating window_bytes) must not reconverge (bug-fix-epoch-11)
- Replay fold pruning: per-lane propose maps are pruned on fold apply (superseded epochs dropped, current epoch retained for same-epoch retry pairing); newest-lane selection uses lane first-seen order, not map iteration (bug-fix-epoch-12)
- Contradiction auto-retract is advisory-only: the 2-token-overlap heuristic had mass-retracted notes (28 distills → 25 retracts), so the pass now emits memory_update{cause:contradiction_candidate} which does not filter recall; retraction only happens via the new `odo retract` CLI or curator supersede (main-epoch-14)
- Learner instrumentation arrived before any threshold changes: batch_superseded journal rows, ledger memory apply accepted/rejected lines per epoch, and a deploy-staleness WARNING (binary mtime >5min older than HEAD) — because the rule layer had silently proposed 30 batches and applied 0 (main-epoch-14)
- AGENTS.md carries only the stable protocol (project rules + odo-todo contract); dynamic memory/pins copy blocks were removed so the model sees exactly one receipted copy (main-epoch-38)
- runMemoryLayers returns errors and assembleRunPrompt refuses to assemble a blind prompt on journal read failure — a blind run must be impossible even though the failure-append itself may also fail when the journal is dead (main-epoch-15)
- Loop-file reads are bounded during read: os.Stat size pre-check plus readWithinDir anchored at the resolved root, then a capped reader enforcing the limit before allocation (growth in the Stat→read window previously forced full allocation) (main-epoch-42)

# Kubernetes Status Integration

- k8s_status is feature-gated: an empty k8s_namespace setting returns available:false reason off immediately with zero exec, and reason classes (off, bad_namespace, ENOENT, timeout, auth, unreachable) are never absent when data is (bug-fix-epoch-50)
- kubectl runs argv-only (get jobs,pods -o json) under a 10s exec.CommandContext with EnrichedEnv and a 1KB stderr cap, never journaled; validation is fail-loud in order namespace charset -> bad_namespace (no exec) -> exec.LookPath -> ENOENT, and KUBECONFIG is extracted from ~/.zshrc (bug-fix-epoch-50)
- Empty-selector queries cap at 50 rows with truncated:true while non-empty selectors query directly with no cap; errors classify as timeout (context deadline), auth (Forbidden/Unauthorized), or unreachable (default) (bug-fix-epoch-50)
- JobsChip polling is visibility-gated (!off && !fold.hidden && docVisible, latched via a visibilitychange listener mirroring App's refreshInbox gate) because every tick is a kubectl subprocess — folded or backgrounded windows clear the interval entirely and fork zero processes, explicitly not OmpUsageChip's always-mounted journal-query posture (bug-fix-epoch-51)
- kubectl stderr is capped at capture time (StderrPipe + io.ReadAll(io.LimitReader(pipe, 1024)) — no unbounded CombinedOutput, no post-hoc slicing) and delivered via K8sStatus.Detail; a stderr flood only blocks kubectl's write side until the 10s deadline kills it, leaving daemon memory unaffected (bug-fix-epoch-51)
- Degradation contract: data may be absent, the reason may never be absent; off-by-config means no chip, tab, or polling, on-but-broken means a visible chip with per-namespace reason rows, and there is no third chip state — partial availability stays a healthy chip with degraded rows (bug-fix-epoch-54)
- At most one k8s_status poller app-wide: state lifted to App via a shared hook, JobsChip a pure consumer, poll gate docVisible && (chip visible || jobs tab mounted-active), with k8s_batch_status riding the same hook/gate — folded chip plus closed tab means zero forks (bug-fix-epoch-54)
- Multi-namespace fan: comma-split/trim/drop-empty-only parsing, fail-loud bad_namespace naming the offending element(s), N<=5 cap and whole-response LookPath before any exec, WaitGroup per-ns goroutines, Namespaces in configured order with flat-merged jobs/pods, the 50-row cap staying per-namespace, OR'd Truncated, and available:true when at least one ns answers (bug-fix-epoch-54)
- Locked kubectl discipline for the batch bridge: get only, exec cat is the only pod-file read verb, --all-namespaces is forbidden (rejected 4/4), with the shared 10s context.WithTimeout and the EnrichedEnv + LimitReader stderr cap reused verbatim (bug-fix-epoch-54)
- k8s_batch_status reads local-mount *.json (depth 1) first with pod fallback via the k8s_job_selector label query (0 hits -> pod_not_found, >1 -> ambiguous_pod, empty selector with no dir -> no_pod_selector), gates on schema_version == 1 with visible schema_mismatch rows labeled by filename (mismatched field names are untrustworthy) sorted to the bottom, and the daemon computes staleness as (now - updated_unix) > 90s and ships both values (bug-fix-epoch-54)
- The k8s settings keys had no UpdateSettings write branches, so GUI writes to k8s_namespace/k8s_context/k8s_job_selector were silently dropped — fixed with non-empty-write branches plus a round-trip test, though clearing a key back to empty still requires hand-editing prefs.md pending a clear-contract decision (bug-fix-epoch-53)
- The jobs tab is a conditional 10th contribution gated on k8sConfigured exactly like the chip; a stored jobs tab fails the PANEL_TAB_IDS localStorage allowlist when k8s is off and lands on tasks (accepted behavior), and progress bars render in the Jobs tab only — the chip face shows counts only (bug-fix-epoch-54)
- docs/design/d5b-batch-status.md pins the batch contract: status.json schema, atomic tmp+rename writes, heartbeat cadence, ownership split (scripts write, daemon reads, schema_version gates upgrades), the 90s staleness rule, and an RBAC honesty paragraph (bug-fix-epoch-54)
- Live-cluster smoke of k8s_batch_status (local-dir read and exec-cat pod fallback) and the multi-ns fan remains outstanding — currently covered only by mock-kubectl harness tests and dev fixtures (bug-fix-epoch-54)
- off is sticky for the page lifetime, so hand-edited prefs.md requires a reload — the accepted price of the no-polling-while-off guarantee; a broken chip keeps 5s polling for recovery detection (bug-fix-epoch-50)

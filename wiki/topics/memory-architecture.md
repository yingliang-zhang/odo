# Memory Architecture & Distillation

- Invariant 1 (ADR-0003): agents write to no memory layer; the daemon is the sole writer, and user.md/global/cross-project layers stay human-written forever. (bug-fix-epoch-19)
- All-user.md batches are intercepted by holdUserScopeBatch before applyResolvedBatch (zero panel spend, journaled scope_held_for_human), and a fail-closed apply-core assert makes planUserApply unreachable from auto paths. (bug-fix-epoch-19)
- Memory apply journals an intent marker before performing writes (marker-first), closing the crash window where a batch is applied but never marked; heal walks all stranded markers with per-layer newest-wins claims. (main-epoch-39)
- Heal must run on the consumed-refusal path and in the auto-gate sweep, not only at boot — otherwise a distill right after a crash retires a stranded marker unhealed. (main-epoch-39)
- The handleApplyMemory consumed branch distinguishes heal-that-completes-the-epoch's-work (returns Applied:true) from heal no-op (keeps rejecting), reconciling the legacy idempotency contract with the crash-window-heals pin. (main-epoch-40)
- A memMu single-writer leaf lock (never touching s.mu/acceptMu) plus journal re-fold under lock for the pending/consumed recheck closes double-consumption and cross-workstream last-rename-wins for both memory batches and pins. (main-epoch-38)
- Human odo memory revert <epoch> is authoritative downstream: evaluate-time revert-ledger checks (not only fold-time) skip recovery over reverted epochs, fail closed on lookup error, and journal an idempotent revert_suppressed_recovery row keyed by (epoch, receipt_layer). (bug-fix-epoch-20)
- Revert restores a pre-image rebuilt from the lane's receipt chain, refusing ambiguity, second reverts, and user.md/skill-touching batches; the replay fold retires reverted epochs' receipts so boot replay cannot repair reverted bytes back to post-state. (bug-fix-epoch-19)
- Retract intents never auto-apply: they ride the batch as an additive retract intent with flag_seq, are panel-gated like any proposal, and accepted ones emit retract_candidate receipts that humans resolve via apply_memory or odo rules retract. (bug-fix-epoch-19)
- The oscillation guard is deterministic from journal rows: retract then re-land within 3 epochs marks the rule frozen in the prompt and rejects further retract proposals via oscillation_guard. (bug-fix-epoch-19)
- Unconsumed memory_audit_flag rows are injected into the learner prompt as a verbatim DATA block with LLM-free vetting — a flag citation must resolve to an existing flag row and a rule present in current memory.md. (bug-fix-epoch-19)
- AGENTS.md carries only the stable protocol (Project Rules plus the odo-todo contract); dynamic memory/pins copy blocks were removed so the model sees exactly one receipted copy. (main-epoch-38)
- The file-write-before-journal-write crash window is deliberately kept benign because normalizeRule dedupe makes replay idempotent — the real gap was the missing concurrent single-writer, which was fixed. (main-epoch-38)
- A project-level outbox replays unconsumed apply markers and pin receipts at boot across all workstreams, globally ordered by store.Event.ID — replacing conversation-scoped recovery that permanently discarded foreign-state intents. (main-epoch-42)
- The outbox replayer re-runs the original planner against the current file (idempotent rebase) rather than replaying raw content, with a retract filter preventing resurrection of retracted rules. (main-epoch-42)
- Explanation-set gating: a file hash is writable only if explained by journal after_sha values or outbox receipts — manual edits are neither clobbered nor cause rule resurrection. (main-epoch-42)
- Wiki topics must be corrected through the daemon's own distill/wiki-commit pipeline, never agent edits — a diff touching protected wiki paths is rejected wholesale. (main-epoch-42)
- Journal changes are additive-key only (ADR-0002 immunity): new payload keys are safely ignored by older consumers, so the GUI needs no changes for additive rows. (bug-fix-epoch-21)

# Panel & Tab Architecture

- Panel tabs derive from a single PANEL_CONTRIBUTIONS registry in contrib.ts: the PanelTab union and PANEL_TAB_IDS re-derive automatically, so removing an entry lets the compiler enumerate every reference site — delete, don't shim, and leave no aliases (bug-fix-epoch-52)
- The tab strip budget is measured, not estimated: 9 tabs ~665px content vs 703px strip client at the 720px MAX restores no-arrow fit, pinned by a PANEL_CONTRIBUTIONS.length <= 9 assertion that must be recalibrated when the jobs tab pushes the strip to 10 (arrows posture accepted then) (bug-fix-epoch-52)
- The ledger folded into Runs as ReviewReceipts.tsx (git-detected rename) mounted inside the Runs keep-alive wrapper with runsEventsRef driving receipts; deep links retarget to the runs tab and the TopBar overflow item to the Preview pathway, while the daemon-side ledger IPC was deliberately retained (CLI surface untouched) (bug-fix-epoch-52)
- Keep-alive doctrine: panels stay mounted for state preservation but refetch on inactive->active transitions with uncommitted drafts protected (an active prop into Wiki/Memory/Ledger/Skills), and the LRU park keeps ~3 tabs mounted with draft-holding editors park-exempt (main-epoch-34)
- The default-tab flip (changes -> tasks) rippled into six specs that open the panel via Meta+j and assert body content; hidden keep-alive bodies need scoped locators (.panel-body > div:not([hidden]) .mem-body) because mounted-but-hidden panels carry the same classes, and the auto-open landing rule (panel-closed lands on Changes, already-open never yanks) needed an e2e pin driven through a real 1->0->1 diff cycle (bug-fix-epoch-49)
- Two real defects found beyond the ripple scope: applyBootstrap must seed the diffs list so the first poll is content-equal (else the Changes tab flips render branches, unmounts, and destroys editor-local state), and accept/reject must update the diffs list optimistically while the e2e mock flips poll-side state or the next poll reverts it (bug-fix-epoch-49)
- UX-1 lifted ChatSurface's internal deriveTodoState to App so PlanChip, TasksPanel, and the badge share one derive (removing a redundant O(journal) fold per poll tick), and the shared TodoList extraction (PlanChip 185 -> 88 lines) makes chip/panel drift structurally impossible; tasks became the registry-first tab with the default flipped in both the useState fallback and panelTabRef (bug-fix-epoch-48)
- Status-bar chip folding keeps chips display:none, never unmounted, so e2e hooks stay alive; hidden state is a dedicated chip-hidden token checked with classList.contains, never a className substring match (which also matched overflow-hidden) (bug-fix-epoch-24)
- The panel overlay uses a hysteresis state machine evaluating docked-equivalent width (chatWidth minus panel.offsetWidth while overlayed) so a naive reading cannot self-oscillate, clamped 280-720px, with empty or unparseable stored widths falling back to default (an empty value otherwise parses to 0 and clamps to 280) (bug-fix-epoch-25)
- Adoption-lock surface conventions: a typed slots.ts data-slot selector map (update slots.ts, never inline selectors), a typed keybind table driving mod-combo dispatch with a ShortcutsPanel, and journal search reusing the existing search_events IPC plus the foreign-workstream switch path — zero new IPC (bug-fix-epoch-26)
- When measurement proves a spec premise unreachable (10 tabs = 730px content vs 659px MAX client, so all-tabs-fit is impossible at any viewport), flip the test to measured truth (controls persist at MAX, both-end tabs reachable via scrollIntoView) rather than weakening it (bug-fix-epoch-48)
- Verified GUI debt gap list: no transcript windowing (full-history fold per event), monolithic App.tsx state, right-pane unmount instead of keep-alive, per-pointermove resize setState, six product concepts in a 380px strip; recommended order is perf fixes -> durable pages vs working panes -> single design contract -> chat column 760-840px with flat replies (main-epoch-42)

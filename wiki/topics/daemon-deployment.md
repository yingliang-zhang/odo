# Daemon Lifecycle, Deployment & Binary Hygiene

- Deployment rule: replace the binary first (cp-to-temp + mv atomic at both <project>/odo and ~/.odo/bin/odo), THEN kill the daemon — ensure_daemon_running would resurrect with the old binary if killed first; verify via go version -m vcs.revision == HEAD and socket health (main-epoch-41)
- Stale daemon binaries cause governance misjudgment: a daemon predating schema v3 auto-rejected diff #36 under the abolished one-vote-veto rule (live DB still schema_version=2 proved v3 code absent), and the same class recurred when a day-old daemon couldn't enforce diff #52's daemon-side fixes — post-restart proofs require vcs.revision match plus behavioral column checks (main-epoch-21)
- Daemon restart kills in-flight agents (graceful-exit SIGKILLs them at main.go:193), so restarts need user go-ahead; a setsid detached resurrect+verify script is the armed pattern; hermes daemon restarts additionally lose its sessions (main-epoch-41)
- Post-restart health verification: full process listing (pgrep false negatives misdiagnosed a running daemon as dead), binary sha three-way match across <project>/odo, ~/.odo/bin/odo and the sidecar-spawned process, nc -U socket probe; log silence ≠ death because serving produces no per-request log lines (main-epoch-33)
- GUI/Tauri layer deploys separately: tauri cold build → ditto replace /Applications/Odo.app → restart, verified by installed-versus-bundle SHA-256; Odo.app can lag the daemon binaries by days and must be rebuilt on GUI-affecting diffs (main-epoch-31)
- Full three-layer staleness inventory pattern: daemon <project>/odo, daemon ~/.odo/bin/odo, /Applications/Odo.app — each tracks a different accept-commitor and a restart plan enumerates exactly what each stale layer is missing (main-epoch-12)
- Deploy-staleness self-witness: git.HeadCommitTime drives a WARNING when the running binary's mtime is >5min older than HEAD, log-only (main-epoch-14)
- SIGBUS crash recurrence from modernc.org/sqlite WAL recovery mmap: remedy landed as connection DSN pragmas mmap_size(0) + synchronous(FULL) on BOTH read-write and read-only open paths (RO shares the live WAL and carries the same SIGBUS class); it is a journaled therapy, not a proven root cause, and production recurrence remains under observation (main-epoch-15)
- Daemon dies stamp an orphan 'daemon restarted while this request was in flight' marker on in-flight chat requests; the bubbles persist in history and do not indicate current failure (UI-epoch-10)
- Disk hygiene: Rust build output dominates dev-directory size (target/debug 5.2GB + target/release 1.1GB vs 108MB everything else); deleting gitignored target/ and node_modules/ shrank the project 6.6GB → 128MB, with tracked source archived via git archive (main-epoch-27)

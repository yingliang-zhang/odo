# Daemon Lifecycle, Crashes & Process Safety

- Deploy ordering rule: swap binaries before killing the daemon — after `kill`, the app auto-respawns the daemon from `<project>/odo` in 1–2 s and an early kill relaunches the old binary; `ensure_daemon_running` is idempotent (flock single-instance + exit-3 attach semantics, no race) (UI-epoch-6) (UI-epoch-5)
- Atomic binary swap via cp-to-temp + mv, then SHA parity verified across `<project>/odo` and `~/.odo/bin/odo` (the global bootstrap for projects lacking a local binary, which had drifted to a stale 8/12 copy and was upgraded in place) (UI-epoch-5)
- GUI app deploy pipeline: worktree fix → commit → FF merge → `npm run tauri:build` in the main checkout (~30–50 s) → `ditto` over `/Applications/Odo.app` → relaunch; deployment is scoped to what actually changed — diff #12 was GUI-only so the daemon binary was deliberately left alone (UI-epoch-2) (UI-epoch-7)
- Definitive installed-app verification without rebuilding: compare installed binary SHA-256 against the `target/release/bundle` artifact, check the running pid's `txt` mapping, confirm main HEAD (this settled a false "install failed" report); Mach-O grep is unreliable for bundle markers because Tauri compresses embedded resources — verify via `gui/dist` markers plus hashes instead (UI-epoch-3) (UI-epoch-5)
- External SIGQUIT killed the daemon mid-`/panel` (`WaitGroup.Wait, 2 minutes` visible in the dump; sender never identified from any repo/system log); hardening fix `installSIGQUITImmunity` logs and discards SIGQUIT while retaining SIGABRT for deliberate dumps — graceful-TERM-on-QUIT was rejected because `srv.Wait` could hang shutdown up to ~24 min on an in-flight panel, losing advisories anyway (bug-fix-epoch-4)
- Boot-time orphan sweep runs first in `NewServer`'s recovery sequence (before any boot recovery writes new expectation rows): every unanswered non-control `user_message` gets an `agent_error{cause:daemon_restart}` closure so the GUI renders a failure bubble instead of hanging; steer/park/`/loop` control rows are skipped, and the sweep self-excludes on next fold so it is idempotent (bug-fix-epoch-4)
- "Resend" bubbles are orphan markers stamped on in-flight requests when the daemon dies; they persist in chat history and do not indicate current failure (UI-epoch-10)
- modernc.org/sqlite WAL-recovery SIGBUS (`_walIndexRecover` memcpy crash) is the only recurring unexpected daemon death signature (2× on 08-11, again 15:36:49); still unresolved — recommended first attempt `_pragma mmap_size=0` in the connection string (one line, zero dependency change), upgrading the dependency only if that fails (UI-epoch-10) (UI-epoch-11)
- hermes-agent daemon restarts handled separately: SIGTERM graceful exit took ~10 s, new PID came up on the doctrine binary, boot recovery logged `1/1 pending diffs already adjudicated — skipping their re-fire`; its pending diff (base `06168c8`) awaits user accept/reject in the GUI (UI-epoch-11)
- Operational gotchas: the shell `kill` builtin refused a session-ancestor PID (external `/bin/kill` worked); bare `odo help` can spawn an unintended daemon; per-project on-demand daemons holding a worktree's odo.sock are normal spawns, not strays; agent bash cwd drifting into a worktree is bypassed with absolute paths (UI-epoch-6) (UI-epoch-7)

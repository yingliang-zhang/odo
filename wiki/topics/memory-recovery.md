# Memory Pipeline & Crash Recovery

- A project-level memory outbox replaces per-lane gating: a boot-time replayer across all workstreams, globally ordered by store.Event.ID, re-runs the original planner against the current file (idempotent rebase) rather than replaying raw content or skipping foreign state - consumed intents are no longer permanently lost when another workstream landed first. (main-epoch-42)
- Explanation-set gating: a file hash is writable only if explained by journal after_sha values or outbox receipts (mem/pins_after_sha) - chosen over hash-equality gating so manual file edits are neither clobbered nor cause rule resurrection. (main-epoch-42)
- Memory apply journals the intent marker BEFORE performing writes (marker-first), with hashes hoisted and unified across cause rows plus two heal functions - the crash window where a batch is applied but never marked is closed. (main-epoch-39)
- Pins are journal-first with heal-before-RMW; reaffirm is a set-to-epoch (not a counter), so double-apply risk is archive duplicates/ordering - marker-first journaling closes the class regardless. (main-epoch-39)
- Heal must also run on the consumed-refusal path and in the auto-gate sweep, walking ALL stranded markers with multi-marker per-layer newest-wins claims - otherwise a distill right after a crash retires the stranded marker unhealed. (main-epoch-39)
- Consumed-batch retry contract: heal that actually completes the epoch's work this call returns Applied:true; heal no-op (already persisted / bootstrap already healed / foreign state untouchable) keeps rejecting - semantic reconciliation in the server.go consumed branch mirroring the in-core path, not test gaming. (main-epoch-40)
- A single-writer memMu leaf lock (never touching s.mu/acceptMu) with journal re-fold under lock closes double-consumption and cross-workstream last-rename-wins for both batches and pins; the file-write-before-journal crash window is deliberately kept benign because normalizeRule dedupe makes replay idempotent - the real gap was the missing concurrent single writer. (main-epoch-38)
- Human memory revert is authoritative downstream: an evaluate-time authority check consults the lane's revert ledger before ANY recovery action (not just fold-time), so reverted epochs never re-apply; lookup errors fail closed to a no-op (no write, no journal row); the revert_suppressed_recovery row doubles as the idempotence record keyed (epoch, receipt_layer); epoch==0 bypasses at zero cost. (bug-fix-epoch-20)
- odo memory revert <epoch> restores a rebuilt pre-image from the lane's receipt chain (fail-closed when unreconstructable), refuses ambiguous receipts and second reverts of the same epoch, and never touches user.md or skill batches (scope: memory.md + archive). (bug-fix-epoch-19)
- All-user.md batches are held for human BEFORE apply-core (scope_held_for_human, zero panel spend) and apply-core asserts autoActor+user.md accepted means fail-closed error, making planUserApply provably unreachable from auto paths - ADR-0003 amended: learner proposals wait for the panel gate, user.md waits for human apply_memory, and user.md/global/cross-project layers stay human-written forever. (bug-fix-epoch-19)
- memory_audit_flag consumption is hybrid: unconsumed rows are deduped (flag_consumed) and injected into the learner prompt as verbatim DATA (evidence, not instructions); vetting is LLM-free - a flag:<seq> citation must resolve to an existing flag row AND a rule present in current memory.md, else retract_proposal_rejected; flag collection is lane-local by design. (bug-fix-epoch-19)
- Retract-intents never auto-apply - they ride batches as additive intent:retract (+flag_seq) gated by the panel like any proposal; the oscillation guard is deterministic from memory_apply rows (retract then re-land within 3 epochs marks the rule frozen and rejects proposals with oscillation_guard); retract intents are excluded from both sets. (bug-fix-epoch-19)
- Fold commits are atomic: store.CommitFold bumps the epoch and writes the marker in one transaction. (main-epoch-23)
- Boot replay is keyset-paginated (512/page, e.id > ? ORDER BY id LIMIT ?, cross-page-equivalence tested) and limit <= 0 is a hard error - never silently clamped to 1<<30; proposeByEpoch growth is pruned on fold apply (superseded epochs dropped, current retained); heal-row window exclusion is count-side only (render predicate unchanged, so heal rows still enter the distill prompt), gated to the replayLayerKind family, and defensively excludes both heal spellings though only recover is emitted. (bug-fix-epoch-12)
- Journal reads are narrowed by LatestFoldBoundary (single-row probe) for distill/auto/autogate reads; a no-pin marker keeps the full-history fallback so the sweep can still rescue pre-pin legacy batches. (main-epoch-23)
- Store/journal query hygiene: SearchEvents escapes LIKE (ESCAPE + likeEscape) and orders by e.id DESC (created_at ties at second resolution); marker JSON value queries match dual colon/colon-space forms via jsonPairMatch/jsonPairNegate OR across all 9 value-bound patterns. (main-epoch-23)
- Store v4 UUID generation is collision-free with a dedicated collision test. (main-epoch-39)
- Contradiction detection is advisory-only: contradiction_candidate rows never filter recall and never auto-retract (the 2-token-overlap heuristic once mass-retracted 28 distills); retraction happens via curator supersede or odo retract <note> [reason...], reversible with odo unretract. (main-epoch-14)
- Learner gate changes are preceded by instrumentation: idempotent batch_superseded rows after the distill marker, per-epoch ledger accepted/rejected/actor lines, and a deploy-staleness witness - 30 batches proposed / 0 applied was invisible before. (main-epoch-14)
- AGENTS.md carries only the stable protocol (Project Rules + odo-todo contract); dynamic memory/pins copy blocks were removed so the model sees exactly one receipted copy. (main-epoch-38)
- Learning control plane (D9-W3): one learning_episode row per lane per distill over the marker-pinned window with outcome classes; append-only .odo/learning/candidates.jsonl writer with creation-time provenance only (sha256 artifact_hash over version/scope/base_sha16/base_source_seq/delta/content); run_usage journaled for ALL runs even when usage data is unavailable (K3); one daemon-side fold serves odo learning status. (bug-fix-epoch-30)
- SQLite DSN hardening: mmap disabled (_pragma=mmap_size(0)) plus synchronous(FULL) on BOTH read-write and read-only opens (the RO path shares the live WAL and the same SIGBUS class) - a journaled therapy under observation, not a proven root cause. (main-epoch-15)
- Journal read failures are never swallowed: runMemoryLayers returns an error and prompt assembly refuses to build a blind prompt - a blind run is impossible by contract, with all four callers' fail-closed paths unchanged. (main-epoch-15)

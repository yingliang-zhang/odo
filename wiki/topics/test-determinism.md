# Verify Gate & Test Determinism

- `capDetail` is tail-biased: it keeps the LAST 4KB rune-safe with an `…[earlier truncated]` prefix — the old head-trim ate the `--- FAIL` lines and made verify_failed blocked rows undiagnosable without reproduction (main-epoch-25, main-epoch-26)
- Full verify output persists to `.odo/verify/<label>-<ts>.log` (1MB tail cap per file, prune to newest 32); the journal keeps the 4KB tail with the log path appended AFTER capping so it is never truncated away; success rows carry a `verify_log` field (main-epoch-36)
- `runVerify` sandbox: scratch HOME + env allowlist; tests asserting 'uninstalled browsers' must `t.Setenv("PLAYWRIGHT_BROWSERS_PATH","")` — an unscrubbed env var made `TestPlaywrightBrowsersDir` a deterministic false-block (main-epoch-25, main-epoch-26, main-epoch-27)
- `goToolchainCacheEnv` pins `GOTELEMETRYDIR=$TMPDIR/odo-go-telemetry` so `go env` subprocess runs stop racing the shared per-user telemetry dir — eliminates the TempDir cleanup flake class (main-epoch-26)
- Verify advisory: when the block reason is `verify_unconfigured`, emit ONE debounced advisory per project per daemon lifetime (`verifyAdviseMu` serializes claim+journal+release; journal first inside the lock, key held only on success); configured-ness is judged from `git show HEAD:.odo-verify` — untracked/staged-only/dirty-past-stub all fail open to advisory (main-epoch-12, main-epoch-13)
- Three-state `.odo-verify` semantics (None/Partial/Ready) with one shared `parseVerifyFile`; a scoped config whose globs miss the diff's paths produces a scope-flavored advisory instead of silent zero-signal; `npm test` is only suggested when package.json actually has a test script (main-epoch-13)
- `.odo-verify` is never auto-created by design: a daemon committing its own verify oracle is exactly what the supply-chain gate must block; discoverability is solved by the advisory instead (main-epoch-12)
- E2E mock timing class: arming `fail` must hold a deterministic window — mock-invoke evaluates `delayMs` BEFORE the fail branch so fail+delay holds then rejects; specs wait on the `bootstrapLandings` counter before arming failure (main-epoch-28, main-epoch-37)
- Poll-dependent assertions use explicit `{timeout: 12_000}` (POLL convention, same family as REFRESH); RPC-local assertions keep the 5s default — introducing a second convention was refused (main-epoch-29, main-epoch-30)
- 'Eventually stably visible' contracts use `expect.poll`, not single-shot assertions — `scrollIntoView`/`scrollBy` run in post-commit effects and race rAF (main-epoch-36)
- Keep-alive hidden panels break page-global `getByText` scoping: assert inside the owning container with a comment pinning the rule (main-epoch-31)
- E2E seeding via one `page.evaluate` `fx.events.push`, not composer sends: 29 run groups in 2.7s vs 48.6s and no 240s timeout (UI-epoch-12)
- Flake adjudication discipline: archive sha16 check → payload attribution → same-worktree `--repeat-each` reproduction; full-suite reruns are negative-information coin-flips and are skipped once isolated stability ≥10/10 (main-epoch-29, main-epoch-37)
- Environmental-lie pattern: every receipt/replay test needs HOME isolation plus a pinned user.md, and every auto-land pipeline test needs scratch-HOME isolation + `review:` arming — single exceptions (`TestRevertEpoch`, `TestAutoLandStartedRowsAbsentBeforeSpend`) passed on configured dev machines and failed only under verify's scratch HOME (main-epoch-25, bug-fix-epoch-20)
- Full-suite runs must override the default 10m test timeout (the suite takes ~500–615s under load); the verify gate itself runs `go test -timeout=14m` after the 8edcbb9 fix (bug-fix-epoch-11, bug-fix-epoch-16, main-epoch-42)
- No repo-wide gofmt reformat: mass churn across untouched files was refused (the project gate is build+vet only); known debt in `loop_audit.go`/`server_test.go` is deliberately retained (main-epoch-20, main-epoch-36)

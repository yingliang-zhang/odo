# Memory Distillation Pipeline (Scheduler & Auto-Guards)

- Daily-cap circuit breaker: on first cap hit per day exactly one `memory_update{cause:"cap_suspended_until"}` journals with the RFC3339 earliest quota release; a single timer aims at that release; resume emits exactly one normal scheduled row — no repeated scheduled/skipped noise, no catch-up storm (bug-fix-epoch-9) (bug-fix-epoch-10)
- Cap feedback-loop root cause: scheduler bookkeeping rows (`scheduled`, `skipped`, `cap_suspended_until`) grew the eligible window they measured (production: 3786→3819 events, 497KB→565KB pure noise); `measureWindow` now excludes scheduler causes from event/byte eligibility while keeping real-activity counting (bug-fix-epoch-9) (bug-fix-epoch-10)
- Render/count split is load-bearing and must not reconverge: `foldExcludedMemoryUpdate` excludes only scheduler bookkeeping from render; `windowExcludedMemoryUpdate` (superset) additionally excludes recovery-family causes (`recover`, `heal_merged`, `heal_conflict`, `heal_resolved`, defensive `heal_replayed`) from window counting — heal rows keep rendering in distill prompts as real history (bug-fix-epoch-11) (bug-fix-epoch-12)
- Window counting exclusion is layer-gated to the `replayLayerKind` family (memory/archive/user/pins/skill:*); same-named causes on note/wiki/auto_distill layers still count as activity (bug-fix-epoch-12)
- Auto-distill spawns and timer callbacks are wrapped into the Server waitgroup and `recoverPendingDiffs` fan-out is tracked the same way; `rig.stop` drains in-flight work — fixes distill writing wiki/journal after store close (main-epoch-42)
- Two auto-review paths differ on `.odo-verify`: diff auto-land hard-depends (fail-closed, blocks as `verify_unconfigured`); memory/wiki auto-gate has zero dependency (`len(models)>0` guards; batch stays pending without review config) (main-epoch-12)
- `.odo-verify` is never auto-created by design — a daemon committing its own verify oracle is exactly what the supply-chain gate must block; discoverability fixed instead by a block-point advisory with three-state None/Partial/Ready semantics, `git.ShowHEADFile` checking committed (not disk) content, and a mutex-serialized claim→journal→release debounce (main-epoch-12) (main-epoch-13)
- Memory/wiki panel auto-adjudication (diff #28): `distillCore` is the single funnel — gate + propose run before the fold marker, auto-apply after it; wiki auto-commit at distill/curate end emits `memory_update{layer:wiki}`; the empty-window guard uses `!unownedFoldGrowth` so pure-bookkeeping windows (wiki telemetry) count as empty (main-epoch-11)
- Fold commit atomicity: `store.CommitFold` performs the epoch bump + marker in one transaction (main-epoch-23)
- Contradiction pass is advisory-only: emits `memory_update{cause:"contradiction_candidate"}` which does not filter recall (2-token-overlap mass retraction was destroying notes); superseded-banner notes are skipped; retraction only via curator supersede or the new `odo retract` CLI (main-epoch-14) (main-epoch-23)
- GUI suspension chip renders "今日额度已用完 · 预计恢复 <time>" from the suspension row with computed fallback (oldest counted distill + 24h) for old journals; chip hidden when auto-distill is disabled (bug-fix-epoch-9) (bug-fix-epoch-10)

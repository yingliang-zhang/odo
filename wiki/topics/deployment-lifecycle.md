# Deployment & Worktree Lifecycle

- Deployment rule: build in the main checkout, atomically replace the binary at both the project path and ~/.odo/bin/odo via cp-to-temp plus mv, then kill the daemon — order matters because ensure_daemon_running would resurrect the old binary. (main-epoch-31)
- Verify the live daemon behaviorally (go version -m vcs.revision, schema_version, socket health) — a 19-hour-uptime daemon was silently running several-diffs-stale code while the journal and store looked healthy. (main-epoch-21)
- Stale daemon binaries misjudge diffs: a running daemon one sha older than HEAD could not enforce freshly accepted daemon-side fixes, so rebuild and redeploy before judging pipeline behavior after any daemon-side accept. (main-epoch-41)
- Graceful-exit SIGKILLs in-flight agents; a prepared setsid-isolated restart script never ran because the GUI restart path superseded it — verify the outcome (old pid gone, new pid, binary revision, socket health) rather than the mechanism. (main-epoch-41)
- The hermes-agent sidecar daemon is a child of the GUI process and dies on app quit, losing its sessions — its restart stayed a pending user decision across epochs. (main-epoch-32)
- pgrep gives false negatives for the project daemon — full ps is the arbiter, and serving produces no per-request log lines, so log silence does not mean death. (main-epoch-33)
- Accepting a diff lands source only: running artifacts (daemon, Odo.app, sidecar) predate the accept and need binary replace, Tauri cold build, and restart before fixes go live; installed odo-gui SHA-256 must match the fresh bundle. (main-epoch-31)
- Disk hygiene: Rust build output was 98% of a 6.6GB project footprint (target/debug 5.2GB, target/release 1.1GB) — deleting gitignored target/ and node_modules/ shrank the project to 128MB with everything rebuildable. (main-epoch-27)
- Worktree discipline: a session's own fresh worktree is the only canonical checkout; sibling .odo/worktrees directories are read-only reference, and worktrees are intentionally left dirty for drain-based diff extraction. (bug-fix-epoch-38)
- The dispatcher repeatedly attached sessions to clean worktrees while the real changeset sat in a sibling — run gates in the tree that actually holds the diff and verify staged-byte identity before drawing conclusions. (bug-fix-epoch-31)
- Lost worktrees are recoverable from the append-only .odo/diffs archive: git apply --3way of archived patches onto current main recovered the complete W4 restoration (22 files, 22/22 clean) when main held only a fraction of the wave. (bug-fix-epoch-35)
- A lost 27-file staged changeset that existed in no worktree was recovered byte-complete from its 265KB .odo/diffs archive via git apply --3way onto main, resolving ours/theirs conflicts per-hunk (theirs = the complete wave). (bug-fix-epoch-36)
- Completed, suite-validated work stranded in a sibling worktree is drained via git diff --cached HEAD piped to git apply --index in the canonical run worktree, with file-count identity checked. (bug-fix-epoch-38)
- Bash harness gotchas: the shell cwd resets per call and the explicit cwd parameter sometimes silently fails — use in-band cd for load harnesses. (bug-fix-epoch-31)
- nohup-launched full suites die when the tool session reaps the process group (log stops mid-packages with no FAIL lines) — launch long suites async and wait via hub. (bug-fix-epoch-35)
- A CLI defect remains: an old binary run inside a worktree path hangs during daemon bootstrap after refusing to register the worktree path; read-only journal commands still work. (main-epoch-27)
- Long e2e runs took 1.6h against an 8–9min expectation with the cause unexplained (machine contention suspected) — investigate before relying on e2e timing budgets. (bug-fix-epoch-31)

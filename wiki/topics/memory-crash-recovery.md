# Memory Distill Crash Recovery

- Marker-first journaling: `applyResolvedBatch` journals the intent marker BEFORE writes, closing the applied-but-unmarked crash window; heals run on the consumed-refusal path and in the auto-gate sweep with multi-marker newest-wins claims (main-epoch-39)
- Idempotent-retry contract: a heal that actually completes the epoch's work returns `Applied: true`; a heal no-op (already persisted/bootstrap healed) keeps rejecting — reconciles legacy `TestUserMemoryIdempotency` with the crash-window pin (main-epoch-40)
- Project-level outbox (`memory_outbox.go`): boot-time replayer across all workstreams, globally ordered by `store.Event.ID`; it replays the PLANNER against the current file (idempotent rebase of intents onto foreign state), not raw content; retract filter prevents resurrecting retracted rules (main-epoch-42)
- Explanation-set gating: a file hash is writable only if explained by journal `after_sha` values or outbox receipts — chosen over hash-equality so manual edits are neither clobbered nor cause rule resurrection (main-epoch-42)
- Boot replay conflict lifecycle: newest receipt per layer decides (disk==after → no-op; disk==before → restore; foreign → entry-merge or `heal_conflict` with embedded stranded body); resolve carries a freshness guard via `disk_sha16_at_conflict` refusing to overwrite moved files (bug-fix-epoch-7)
- Supersession retires conflicts: when a layer's newest receipt is LANDED, older OPEN conflicts are journaled `heal_resolved{actor:"superseded"}`; retirement fires only under project-wide fold context, and legacy terminal-landed receipts retire older conflicts too (bug-fix-epoch-7)
- Sweep repair: `sweepPendingBatch`'s consumed-batch early return takes `memMu` and re-folds the journal fresh, so a live failed-write marker repairs at sweep time instead of waiting for the next apply or restart (bug-fix-epoch-8)
- `memMu` single-writer leaf lock (independent of `s.mu`/`acceptMu`): `applyResolvedBatch` re-folds journal under lock — closes double-consumption and cross-workstream last-rename-wins for memory batches and pins (main-epoch-38)
- P1-1 crash window (file write before journal write) deliberately kept: `planMemoryApply` replay-idempotent dedupe makes the window benign; the real gap was the missing single-writer lock (main-epoch-38)
- Recovery invariant: store migrations only UPDATE/ALTER so archived-lane receipts survive physically; `ListProjectEvents`/`ListHealLedgerRows` use LEFT JOIN as a query invariant; hard cascade-delete or whole-journal rotate = unrecoverable by construction (bug-fix-epoch-7)
- AGENTS.md carries only the stable protocol block; dynamic memory/pins copy blocks removed so the model sees exactly one receipted copy (main-epoch-38)
- distillCore is the single funnel: gate + propose before the marker, auto-apply after it; wiki changes auto-commit at distill/curate end emitting `memory_update{layer:wiki}`; empty-window guard defined via `unownedFoldGrowth` so pure bookkeeping windows count as empty (main-epoch-11)
- Curator supersede mechanism: curator declares `superseded` notes; daemon validates (name ∈ notesRead ∧ cited by ≥1 written bullet), stamps a SUPERSEDED banner atomically; file stays on disk for citation liveness while recall injection skips bannered notes (main-epoch-6)

# Learning Control Plane

- Candidates arise only from accepted learner-batch proposals on the existing autoApplyProposals path (learning_stages pref ON) and are diverted into candidate rows instead of writing memory.md directly; retract deltas stay human-originated; send returns at zero cost when candidates.jsonl is absent (bug-fix-epoch-32)
- artifact_hash = sha256 over {version, scope, base_sha16, base_source_seq, delta, content} using the same planMemoryApply pure function replay uses; the journal row is written before the jsonl row so append-only dedupe holds — crash-replay with the same base_source_seq is an idempotent no-op (bug-fix-epoch-32)
- All learning gates are LLM-free and deterministic: lint (bounds, format, dup-free, retract targets exist, evidence notes, R2 freeze-set) and frozen replay over an 8-epoch slice; missing inputs ⇒ verdict unverifiable = FAIL (fail-closed), which is correct semantics independent of determinism (bug-fix-epoch-32)
- The stage machine is journaled-transitions-only (candidate→shadow on lint+replay pass, →dropped on fail, shadow→canary on ≥3 epochs + regrown-slice re-pass + free slot, any→frozen on R2); stage status is journal-fold, never stored on the jsonl row, and shadow checkpoints re-run replay against the grown slice at each main-lane distill (bug-fix-epoch-32)
- Canary seam: deterministic interleave (ordinal % M == 0), zero RNG, assignment journaled before the run, steer-continuations inherit the cohort; injection substitutes candidate content inside runMemoryLayers with no new receipt keys, and canary outcomes are excluded from live rows and baseline (bug-fix-epoch-32)
- Never-score-own-changes: one shared excludedFromScoring predicate (gate-source ∪ memory-path ∪ learning-plane) mirrored into rules-audit; fail-closed unknown⇒excluded applies only to frozen replay while live audit keeps the legacy truth posture for unreadable patches (bug-fix-epoch-32)
- W3 observability: one learning_episode row per lane per distill over the marker-pinned [first_seq, last_seq] window; run_usage rows journal for ALL runs (usage_available:false when data is missing — K3 fail-soft), and verify_ms is fail-soft on verify outcomes (bug-fix-epoch-30)
- candidates.jsonl is append-only with creation-time provenance only, and learning_status is a single daemon-side fold (episodes + stages + flags) surfaced via the `odo learning status` CLI and the MemoryPanel Learning tab (bug-fix-epoch-30)

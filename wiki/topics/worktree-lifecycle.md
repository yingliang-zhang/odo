# Worktree & Run Lifecycle

- The run's own bound worktree is the ONLY canonical checkout - staging fixes into a sibling worktree (the origin run's or another lane's) makes drainRun extract an empty diff and the origin diff wedges pending forever with no agent_error; recovery is extract-to-tmp plus a zero-change re-snapshot run that binds a fresh worktree and re-applies the patch in one pass. (bug-fix-epoch-12)
- Reject destroys the candidate worktree, leaving the archived .diff as the sole survivor - rescueResolvedWorktree snapshots the pre-retirement full delta (only when it differs from the archived patch) to .odo/diffs/<run>-rescue.diff with rescue receipt fields appended to the resolution row; reviewed patch bytes are never rewritten. (main-epoch-35)
- .odo/diffs/ is an append-only, sweeper-exempt archive - not a live queue; accepted patches stay on disk permanently (77+ retained), so no queue-clearing is needed after accept. (main-epoch-22)
- retireRun must select the diff's own run by matching worktreePath against s.runs (byConv binding only as fallback, reaped only when it points at the closed run) - otherwise reviewing an older diff closes a newer run's worktree and session, and can kill an in-flight auto-land verify causing spurious verify_failed. (main-epoch-28)
- delete_workstream hoists the deletingWs flag unconditionally BEFORE the conversation lookup, and bootstrap's create section runs under the same lock with the guard - a conversationless lane previously allowed bootstrap, delete, then bootstrap-creates-conversation under a deleted workstream. (main-epoch-42)
- Before SQL delete, the daemon checks in-memory active state (run/distill/distillKind/slash/panel/loop/autoPending) then journal-derived loop activity - blocking hidden diffs on soft-deleted workstreams; a sub-second guard-check-to-delete race remains, classified user self-inflicted with the store's pending-diff check as backstop (full atomicity needs deletion moved into the run state machine). (main-epoch-38)
- An atomic registration guard (a Server field wired at every run-start site: send-message tail, slash routes, auto fire/arm, the preview slash slot, distill entry, loop start) prevents duplicate run starts - handleSendMessage holds s.mu for its whole body while slash routes lock inside their own handlers. (main-epoch-39)
- Auto-distill spawns, timer callbacks, and the recoverPendingDiffs fan-out are wrapped into the Server waitgroup; rig.stop drains in-flight work (measured 3.7-3.9s) - untracked goroutines once wrote wiki/journal after TempDir cleanup and store close (database is closed, 1-in-3 race reproduction). (main-epoch-42)
- recover-pending-diffs re-fires pending diffs at daemon restart (panel_infra's designed resolution) and excludes loop-owned seeds. (main-epoch-16)
- Orphaned commits stranded on a deleted worktree's detached HEAD are recovered by clean cherry-pick into main plus --ff-only in the primary repo, with a journal correction declaring the earlier false claim invalid. (main-epoch-20)
- Port discipline is stop-don't-improvise: any git apply --3way hunk failure halts the port for reporting, and a port is only attempted after verifying the HEAD delta has no overlapping paths with the payload. (bug-fix-epoch-29)
- Worktrees lacking gui/node_modules get a real npm ci (3s, lockfile untouched) - a symlink to the main checkout passes tsc/vitest but breaks Playwright with dual-instance beforeEach exceptions. (bug-fix-epoch-30)
- Migration v4 dedupes fossil duplicate workstream names (the new id keeps the name, the old gets -dup-<id>), adds a partial unique index on status=active, and CreateOrGet re-reads the winner row on constraint conflict; the index is deliberately EXCLUDED from schemaV1 unconditional DDL because legacy DBs need dedupe first (fresh DBs record version=4). (main-epoch-38)
- Concurrent panel progress is a per-consult batch-group slice: defer removes only its own batch and poll snapshots merge, so concurrent panels no longer show Done > Total or mixed legs. (main-epoch-38)

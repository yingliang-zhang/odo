# Testing & Verify Gate Reliability

- capDetail 4KB head-truncation ate the '--- FAIL' lines from verify failure details (blind diagnoses on #40, 47, 48): full gate output now persists to .odo/verify/<label>-<ts>.log (1MB tail cap per file, prune to newest 32), the journal keeps a tail-biased 4KB excerpt, and the full-log path is appended AFTER capping so it can't be truncated away (main-epoch-36)
- Verify reproduction needs faithful conditions: same byte set, scratch HOME, and the allowlisted env; the gate runs under a scratch HOME since credential isolation, so tests touching review prefs or HOME-dependent globals must self-isolate with t.Setenv (TestAutoLandStartedRowsAbsentBeforeSpend's missing HOME+review: arming line was the #39 block) (main-epoch-25)
- TestPlaywrightBrowsersDir was environment-sensitive (verify injects PLAYWRIGHT_BROWSERS_PATH when a host ms-playwright cache exists) — deterministic-demonstrated A/B proof (fail with the var, pass after t.Setenv scrubbing) is the model for displacing 'flake' claims (main-epoch-26)
- Go verify suite runs ~535–615s under load vs a default go test 10-minute timeout; a failure at exactly 600.45s is the -timeout wall, not a deadlock, and the pipeline runs with an explicit extended -timeout=14m (bug-fix-epoch-16)
- Playwright poll-dependent assertions use the pre-existing POLL = { timeout: 12_000 } convention (journaled bubbles, heartbeat N/M, panel legs, queue rows all ride the 1.5s poll loop and can miss the 5s default under load); RPC-local assertions stay at the default — adding a second convention was refused (main-epoch-30)
- rAF-racing assertions (scrollIntoView/scrollBy run in post-commit effects) become expect.poll polling retries — the contract is 'eventually stably visible', not instantaneous state (main-epoch-36)
- Mock design principle: the fail branch must evaluate AFTER delayMs so arming failure holds then rejects in a deterministic window; single-shot sampling outside that window flakes at design level (switch-cache :64 root cause), and per-workstream bootstrapLandings counters give specs a wait-for-commit landing signal before arming failure (main-epoch-37)
- Keep-alive panels render hidden components to the DOM, so page-global getByText assertions match invisible copies forever — scope assertions to their container (.review-inbox) and grep the repo for the same pattern (main-epoch-31)
- Flake-classification rule: load-sensitive verify failures (gate concurrent with idle distill/wikicommits) that pass isolated reruns on identical bytes are accepted manually rather than re-run — a rerun is a coin-flip re-block with zero information gain (main-epoch-36)
- 'Fix one, audit all': every same-class site is swept after a diagnosed defect (mock fail+single-shot sampling sweep, POLL-tagging sweep of 15 poll-dependent assertions, stale Assertion sweep after guard log-text change) rather than patching only the failed line (main-epoch-37)
- No repo-wide gofmt reformat: the gate is build+vet only and new gofmt versions flag untouched files, so mass churn refused; known gofmt debt (loop_audit.go, server_test.go) is deliberately retained and recorded (main-epoch-36)
- Test fixture seam over UI-bootstrapping: e2e state (29 run groups) injected via page.evaluate against the fx.events fixture seam in 2.7s vs 48.6s of composer sends — and assertions derived from boot DOM state so they survive fixture drift (UI-epoch-12)

# Panel Review (MoA) & Settlement

- Panel = three synchronous MoA legs (kimi-k3, glm-5.2, deepseek-v4-flash); every leg goroutine and every review funnel (reviewWithModel, /vision, /preview) carries an outer WithTimeout deadline; the theoretical 5-slot x ~24min tail-leg starvation producing a false panel_infra remains accepted fail-closed (main-epoch-15)
- Infra failure is never a verdict: provider 401s/EOFs block or abstain, never pass; panel_infra is the only non-terminal blocked reason whose designed recovery is the daemon-restart re-fire, and the restart waits for token refresh before re-firing (main-epoch-17)
- Settlement semantics: rounds 1-2 require unanimous accept (any reject auto-rejects, fail-closed unchanged); terminal round 3 runs the majority valve — >=2/3 accept with zero rejects/infra/truncated, journaled as majority_accept — and its only reachable composition is exactly {2 accept, 1 needs_fixes} (main-epoch-21)
- Diverged panels (panel_mixed) enter the repair ladder instead of instant auto-reject; if divergence persists past 3 review-and-fix rounds a strict majority (>1/2 accepts) decides land vs reject, else suspend for human review (main-epoch-19)
- Truncated legs are downgraded to needs_fixes at verdict construction and explicitly abstained in the cap-count loop — a truncated leg can never shrink the majority denominator N (main-epoch-20)
- Gate-source diffs (the pipeline's own autoland/settle/risk code) permanently require panel unanimity and route to ladder_suspended on valve-shaped outcomes; the majority_accept attestation path was deleted after a 2/3 panel could otherwise land its own gate-weakening (main-epoch-14)
- patch_sha16 byte-binding: panelVerdictAttestsDiff ties the verdict to the exact landing bytes (consensus='accept' only), so acceptance evidence cannot be replayed onto a mutated patch (UI-epoch-11)
- The review objective is stored at diff creation (schema v3 diffs.goal) and consumed via diffGoal() with originGoal as legacy fallback only — re-scanning the session's last human message had wrongfully rejected diff #34 on an unrelated later message (main-epoch-18)
- With a single review model configured the panel is unarmed (one judge gives no consensus), emitting a once-per-daemon auto_land_blocked{single_judge_panel} advisory; run-state evidence (run_errored) is checked before the config advisory so an errored run never burns the once-per-lifetime notice (main-epoch-15)
- Panel claims are triaged against source before acting: epoch-33 adopted 1 of 3 deepseek charges (sameAutoDistillList duplicate-id hole — fixed with consume semantics plus tests) and rejected 2 as unreachable; fabricated or moot charges are answered with evidence, not code churn (main-epoch-33)
- Cost guards: the 87K repair-prompt breaker estimates ASCII/4 + 1 token per non-ASCII rune (old len/4 underestimated CJK ~3x); the repair chain is hard-capped at 64KB (main-epoch-23)
- MoA calls share one Server-level client with a concurrency cap (NewClientFromEnv call sites converged, runMoaOneShot re-signatured), pinned by tests (main-epoch-16)
- Proof-packaging lesson: the panel reads only the diff packet, so a goal describing a one-line doc fix over a ~1250-line code packet fails review regardless of code quality — diff #74 took 7 rounds and landed only after a zero-code-change repack with a goal matching the packet (bug-fix-epoch-6)
- Slash consults (/panel, /vision) surface through existing channels only: they count into running_workstreams (blue/purple dots, StatusBar chips) and report per-leg progress via poll_events — zero new RPC or journal kinds (main-epoch-8)
- Panel progress (panelProg) is memory-only, never journaled, and is now a per-consult batch-group slice with defer-removal scoped to its own batch — concurrent panels no longer show Done > Total or mixed legs (main-epoch-38)

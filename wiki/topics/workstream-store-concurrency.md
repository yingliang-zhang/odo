# Workstreams, Loops & Store

- delete_workstream vs bootstrap atomicity: the deletingWs flag is hoisted unconditionally before the conversation lookup and bootstrap's create section runs under the same lock with the guard — closing the conversationless-lane race where delete could be followed by bootstrap-creates-conversation under a deleted workstream (main-epoch-42)
- Deleting an active workstream is refused after checking daemon in-memory state (run/distill/slash/panel/loop/autoPending) then journal-derived loop activity; the accepted residual is a sub-second race between guard and SQL delete, classified self-inflicted with the store's pending-diff check as backstop (main-epoch-38)
- Run-start duplication guard: one atomic registration flag wraps every start site (send tail, slash routes, auto fire/arm, preview slot, distill entry, loop start), and handleDeleteWorkstream is restructured around the same atomic flag (main-epoch-39)
- Loop admission is atomic: state fold + loop_started journal append happen in one critical section on both start paths (the early fold outside the lock survives only as a fast-reject hint); a 4-goroutine -race pin yields exactly one winner (main-epoch-15)
- retireRun selects the diff's own run by worktreePath match (the byConv binding is fallback only, reaped only when it points at the closed run) — reviewing an older diff can no longer delete a newer run's worktree or kill an in-flight auto-land verify (main-epoch-28)
- SQLite DSN hardening: mmap disabled and synchronous(FULL) on BOTH read-write and read-only opens (the RO path shares the live WAL and carries the same SIGBUS class); the modernc.org/sqlite WAL-recovery SIGBUS remains a journaled therapy, with the memcpy root cause unproven (main-epoch-15)
- Schema v3 added diffs.goal via atomic v1-to-v3 and v2-to-v3 ALTERs with fresh DBs recording v3 directly and migration tests pinning both paths (main-epoch-18)
- Schema v4 dedupes fossil duplicate workstream names (winner keeps the name, loser gets -dup-<id>) then adds a partial unique index on status='active', deliberately excluded from unconditional v1 DDL because legacy DBs need the dedupe first; CreateOrGet re-reads the winner row on constraint conflict (main-epoch-38)
- The store-layer v4 dedupe path was made collision-free, backed by a dedicated v4 collision test (main-epoch-39)
- Query correctness: SearchEvents escapes LIKE metacharacters (ESCAPE backslash) and orders by e.id DESC (created_at second-resolution can tie); marker JSON queries match both colon-space encodings via dual-form OR (main-epoch-23)
- The /loop audit subject cap is loop-owned at 256KB (chosen to fit squash-merged feature diffs, e.g. the 233KB M19 commit; beyond 256KB is a hard wall); the 16KB findings-feed wall, severity gate, infra-is-never-a-verdict, stall and closure guards stay unchanged (main-epoch-5)
- Ledger reconciliation convention: divergences (store says rejected, git says landed) are healed by append-only journal correction rows carrying corrects_seq, refuted claims, and landed commit hashes — store statuses are never silently mutated (main-epoch-27)
- Cost honesty and fold efficiency: Escalation.InputTokens records the re-paid prompt cost of abandoned max-token requests on each bump, and the loop fold decodes each row payload once instead of 2-4 per-key decodes (main-epoch-23)

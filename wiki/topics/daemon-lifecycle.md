# Daemon Lifecycle & Deployment

- Deployment rule: build from main HEAD, atomically replace BOTH binaries (cp-to-temp + mv at <project>/odo and ~/.odo/bin/odo) BEFORE killing the daemon — ensure_daemon_running resurrects from whatever binary is on disk — then verify vcs.revision==HEAD plus socket health; GUI-only diffs skip the daemon rebuild entirely (main-epoch-31)
- Post-accept deployment is the gate for daemon-side semantics: diff #52's heal/skills/run-guard fixes were inert on a day-old binary until both locations were rebuilt from dd75b0f with three-way sha equality and the GUI respawned the daemon (hermes sidecar refreshed too, per-project stores unaffected) (main-epoch-41)
- A stale daemon once auto-rejected diff #36 under abolished one-vote-veto rules and never ran the schema-v3 migration (live DB stayed v2, proving v3 code absent); restart verification must check behavioral markers (PID, socket, schema_version, diffs.goal column), not process liveness (main-epoch-21)
- Graceful daemon exit SIGKILLs in-flight agent processes (main.go:193), so the reliable restart path is a GUI full restart rather than an in-band daemon_restart that would orphan the very request asking for it (main-epoch-41)
- landWG accept-tail lifecycle: every run pre-adds a lifetime pin inside one s.mu hold in bindRunLocked, so any drain-tail Add provably precedes landWG.Wait; sealLandAndReleasePins closes admissions and sweeps pins in one critical section — late binds refuse (never hang), and drain-internal retires skip release since pin release is owned solely by drainRun's top defer (bug-fix-epoch-6)
- runLivenessDrain (2s interval, atomic toggle) mounted in NewServer lets GUI-closed agent runs keep progressing — closing the documented 'GUI-closed loops continue' falsehood for agent-run phases, which previously drained only on poll (main-epoch-14)
- SIGQUIT is discarded via signal.Notify + log rather than honored with a graceful shutdown that would hang up to ~24min on in-flight panels; SIGABRT is retained for deliberate stack dumps (bug-fix-epoch-4)
- Boot recovery runs the orphan-request sweep FIRST in NewServer: unanswered non-control user_messages get agent_error{cause:daemon_restart} closure rows (self-excluding on refold), turning the 'resend bubble' zombie-request class into a visible closed failure (bug-fix-epoch-4)
- Session/prompt hygiene: session dirs delete at run retire, but prompt files deliberately survive retire (consumed as audit ground truth by steer-retry tests) and converge via boot-sweeper aging; dead brief/output files were one-time legacy cleanup with no hook to add since the daemon never writes them (main-epoch-6)
- The registry refuses auto-registration of linked git-worktree paths (.git file pointing into .git/worktrees/), submodules still allowed; phantom mktemp projects are removed via the sidebar remove-project escape hatch (main-epoch-6)
- Deployment verification is artifact-based, never verbal: sha equality across both binary locations, app bundle vs installed-app sha, PID start order strictly after binary install, socket answering, journal writing in real time (UI-epoch-6)
- Watch the 10-minute default: adding memory boot-fold + drain pushed the ~575s ipc suite baseline over go test's default -timeout (one run failed at exactly 600.45s) — diagnosed as deadline, not deadlock; full suites now need an explicit extended -timeout (main-epoch-42)
- Lost unregistered work is recoverable byte-exact by replaying write/edit payloads from the journal transcript (sessions/<id>/output.txt) — the epoch-11 doctrine change was rebuilt from 24 replayed payloads after its run died mid-registration with the worktree wiped (UI-epoch-11)
- Test teardown idempotence: stopflight sync.Once + stopOnce(t) helper, with a post-migration census showing zero bare mid-test rig.stop(t) calls — all pre-existing crash drills converted (bug-fix-epoch-6)
